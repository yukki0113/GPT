## 2. JSON内容の検証

- トップレベルキー: `date`, `regulation`。JSON正常パース。
- `regulation` のキー: 数字文字列の**KONAMI ID**。**カードの8桁パスコードやYugipedia記事IDではない**。
- 値: デッキ採用可能枚数の `0 / 1 / 2`。スキーマで定義され、0=禁止、1=制限、2=準制限に対応。
- **計215件**：0が**114件**、1が**77件**、2が**24件**。
- `3` は列挙しない差分形式。**掲載なし=3枚可**という解釈は通常ルールに沿う想定だが、MDカードの存在・使用可否、イベント特別規則等の検証が必要。欠番を禁制「なし」と短絡しない。

## 6. 再現手順

1. 3ファイルのraw SHA-256を固定（参照: [原データ保管マニフェスト](P0_SOURCE_ARCHIVE_MANIFEST.md)）。
2. `json.load` で `current.vector.json` の `date` と `regulation` を読み、`Counter(regulation.values())` で件数を確認する。
3. `cards.json` の `konami_id` から `str(konami_id) -> list[card]` を作り、ベクトル215キーを全件照合する。
4. 解決されたカードの `name.en` をMD専用JSONの `en_name` と照合する。必要ならNFKC・記号前後の空白を正規化し、同名異カードを分離する。
5. 照合表・全件正規表の本文をGit公開側へ出力せず、件数と差異・証跡を集計する。
6. 9枚の改訂対象は日本語攻略記事の上限区分と一致するか検証する。

監査メトリクスは [P0_LIMIT_REGULATION_METRICS.json](P0_LIMIT_REGULATION_METRICS.json) に固定。
