# M6-5C 受入監査 — 所持汎用札で締めるMAIN/EX再構成初版（2026-11-12）

## 目的

M6-5Aでテーマ内N/R/SR・所持汎用・出張・属性/種族/レベル・汎用EXを検索し、M6-5Bで効果本文・素材/依存カードの根拠を確認する基盤を整えた。M6-5Cは、これらを**単なる候補リストで終わらせず、テーマ中核を先に置き、所持済み汎用で残りのMAINを補い、EXを別途再構成し、純テーマ/出張/混合の複数案を比較する**構造アルゴリズムの初版である。

重要な境界：**M6-5Cの成功は、実際に対戦で通用する強い完成デッキの証明ではない**。候補の「役割」「優先度」はAI/人間の出典付き評価入力であり、数学的・ゲーム内の性能検証値ではない。所持UNKNOWN/現行MD規制未検証を勝手にPASSに昇格させない。

## 新規コード：`engine_m6/recompose.py`

- 外部で原本SHAを検証して得た`M6-5A discovery`候補集合を入力。教師レシピに存在しないカードも同じ出典付きDBカードとして扱う。**本関数自体は原本バイトを再取得/再検証せず**、与えられた検証済み検索結果の世代SHA一致だけを確認する。private本番一気通貫はM6-6で実施。
- 各候補はカードID、MAIN/EX、テーマ中核/テーマ任意/別テーマ/所持汎用/所持出張/テーマEX/汎用EXの区分、役割、数量下界と上界、優先度、出典、効果レビュー状態、出張IDを持つ。**生の効果や正しい戦術性を関数が創作しない**。
- 最低限のテーマ中核を先に確保し、必要な出張はパーツ単位でまとまって投入。MIN<=MAX<=3、所持確認済み汎用・出張は手持ち枚数以内、未所持/UNKNOWNを所有済みにしない。COREテーマのURは既定LOW_RARITY_COREで不採用。所持済みの汎用URは利用可能。STRICT_NO_URでは所有済みURも不採用。
- MAINは最低40枚（ユーザー要求のmain_minが大きければそれを優先）を目標として確定した戦術中核から着手し、妨害・後攻対応といった役割別候補を追加。**テーマ/出張を約28枚まで優先してから所持汎用で仕上げる戦略**は検証前の構造ヒューリスティックであり、これを最適値・勝率と呼ばない。40枚に届かない時は架空カードを詰めず`NOT_ENOUGH_SOURCED_MAIN_CARDS`。
- EXTRAはM6-5B素材確認が`POSSIBLE_ON_PAPER`の候補のみ別途検討し、要求上限15を超えないよう調整。未照合素材EXは`EX_MATERIAL_NOT_DEMONSTRATED`として保留し、教師EXのURを抜いた7枚だけで完成とはしない。パッケージの必須EXカードも同様に素材根拠が未確認なら採用案ごと棄却。
- **純テーマ / テーマ＋所持出張 / 混合再設計**の別案を固定順で列挙。出張禁止指定（allow_engines=false）、必要パーツ不足、パッケージ同士の競合、解決していない選択肢を検出する。MAIN/EX内訳・使用EX枠・役割別採用数・不足役割・候補棄却理由を返す。同じカード集合は重複案として除外。
- 生成された構造候補をM6-5Aの`rebuild_from_discovery`とM6-0`validate_candidate`で再検査。返却状態は必ず`STRUCTURAL_RECOMPOSITION_REVIEW_REQUIRED`、`gameplay_tested=false`、`recommendation_eligible=false`。M6-4で所持・N/R/SR/UR生成CP・最新規制、M6-5Bで実際の効果/ロック・必要素材、M6-5Aで探索全件と不採用理由を再評価するまで完成推奨に昇格させない。

## 未解決事項と次の手順

1. **実装境界**：本版は出典付き役割注釈を受け取る自動選別・構造再構築エンジンであり、AIがカードの役割を根拠付きで読み取る段階を自律的に完走する完全なオーケストレータではない。現在の役割目標（STARTER9/INTERRUPTION6/BOARD_BREAK2）は単なるヒューリスティックであり、実戦成績の統計ではない。
2. **戦術的妥当性**：M6-5Bの`POSSIBLE_ON_PAPER`は実際の素材展開・MD合法性の保証でない。出張固有の召喚制約/衝突、役割タグの正しさ、初動の実効成功率を検証する必要がある。
3. **M6-6：private統合試験**：M5-C bundle → 最新M6-1 preflight → M6-5A DB discovery/role review → M6-5B material/effect/package review → M6-5C portfolio recomposition → M6-4 regulation/owned/CP evaluation → M6-5 comparison/private不変保存を、**同じ検証済みGen5原本の実データで実際に実行**。軍貫EX7を不合格の基準例とし、探索の改善で何枠が適切か評価する。他3テーマも不足資料を補完せずレビュー段階で止める。
4. **M6-7：構築スレッド受入**：ユーザー条件に応じた提案の質を、手持ち優先・既定LOW_RARITY_CORE・STRICT_NO_UR・SR以下などのケースで確認する。
