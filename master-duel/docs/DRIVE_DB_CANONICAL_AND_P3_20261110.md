# Drive DB 正本と次工程 — 2026-11-10

## 正式保存先

Google Drive の `GPT/MasterDuel/DB/`（既存フォルダ）を、今後の **Master Duel SQLite ZIP と正本参照メタデータの保存先**とする。Drive ルートの旧 `master-duel-private-db/` から移した7ファイルと既存3ファイルの計10ファイルを確認。旧フォルダは空。フォルダ・各ファイルは共有制限（所有者のみ）を確認。**フォルダの公開共有は不要**。公開GitHubに個人所持情報や私的DriveのファイルIDを含む操作用資格情報を置かない。

## 正本判定のルール

- **本番DBの唯一の正本参照**: `MD_CURRENT_HEAD.json` の `scope=PRODUCTION` と `current_snapshot`。現状は `generation=0`, `classification=EMPTY_PRODUCTION_BASELINE`, `schema_version=1`, **0件の空DB**。
- **合成テスト専用**: `P2B_TEST_CURRENT_HEAD.json` の `scope=SYNTHETIC_TEST` と `current_snapshot`。現状 `generation=1`, `classification=SYNTHETIC_TEST_ONLY`, **架空カード2件**。これは本番に昇格させない。
- 旧 `master_duel.sqlite.zip` は参照・保管用の初期ZIP。**ファイル名の似たZIPや最大更新日時から正本を推測しない**。
- JSONは更新前に最新のDriveから再取得し、参照先ZIPのハッシュ、スキーマ版、`integrity_check`、`foreign_key_check` を確かめる。実更新前にプライベートなバックアップと不変の新スナップショットを作成し、独立に再取得・SHA照合する。
- 現行のGoogle Driveコネクタ `update_file` に **条件付き更新/atomic CAS がなく**、head JSONの変更前後照合だけでは競合を完全には防げない。**単一ライター作業スレッドのみ更新可**とし、音声スレッドは候補作成に限定。競合・参照不明・検証不可・失敗時は正本切替しない。複数ライター安全性は保証しない。
- 実カード本文の取り込み・利用条件が未確定の大量DB化は `P1-A1 NO-GO` 維持。現行本番DBへ架空データを入れない。所持カードの実記録は正確なカードID照合と権利・出典ゲートを分けて判断する。

## 2026-11-10 配置照合

移動元7ファイルを既存 `GPT/MasterDuel/DB` に移動し、既存3ファイルを保持。10/10同フォルダ、名前重複なし、ID不変、所有者のみの共有設定。旧一時フォルダ0ファイル。元データのZIP内容を変更した操作ではない。P2のZIP作成・書込・再取得・SHA照合は前工程の実地検証、競合の原子性は未達。これを **P2単一ライター限定の運用基盤完成** とし、マルチライター自動CRUDには拡張しない。

## 次工程：P3 所持音声入力のステージング・カードID照合契約

優先対象は音声スレッドから **カード名と枚数を一括入力**できる安全な受け皿の実装。カードマスター未整備の現段階では、本番DB更新を強行せず、名称だけの入力を **未解決候補** として保管する。

### 受入要件

1. JSON/CSV入力（カード名、枚数、入力バッチID、由来、元の読み上げ候補）。表示名を自動でID生成しない。
2. NFKC/casefold/空白除去等の既存名称正規化を再利用。カードIDで一意に解決できた行のみ `RESOLVED`、0候補は `UNRESOLVED`、複数候補は `AMBIGUOUS`。推測一致は自動確定しない。
3. 1バッチの全件が一意に解決するまで本番DB変更を禁止。更新候補とDB現在値の差分プレビューを作成し、人が確定できる形で返す。
4. `SET_INVENTORY` のP1契約を再利用し、冪等なバッチID・衝突拒否、`UNKNOWN` と確認済み0の区別、取り消し可能な履歴。音声スレッドから直接Driveへ書き込まない。
5. ステージングは **プライベート領域のみ**。公開Gitには合成fixture・コード・テスト・仕様のみ。ファイル移動や新スナップショット作成の際も単一ライター/再取得確認。
6. 合成データのみで、重複名、表記揺れ、発話訂正、再送、枚数異常、カードID衝突、途中失敗、誤った本番反映防止のテストを作成。
7. カードマスターの実投入はP1-A1判断が別途必要。未解決候補を勝手に「登録済み所持」と報告しない。

### 実装経路

複数Pythonモジュールとテストを伴うため次工程の実装担当は Codex Cloud。実Drive運用・権限・参照実測とマージ監査は ChatGPT/Work で実施する。Codex は最新mainとこの指示を読み、P3のコード・テスト・READMEをPRにまとめる。単独で本番Driveのheadを更新しない。
