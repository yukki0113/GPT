# MD 音声台帳登録スレッド — 汎用カード所持・所持デッキリスト（2026-11-10）

- 状態: 運用仕様 v1.0。2026-11-10時点の既存 `voice_staging` / `inventory_m2` を活用するためのスレッド仕様。**音声認識ツールの実装・デッキ登録先DB schema・本番デッキ保存の実装が完了したという意味ではない**。
- GitHubは公開仕様・架空テストのみ。個人の実所持、実デッキ構成、発話原文、確認用バッチは非公開Driveにのみ保存する。
- 主目的は初回大量登録。大量投入よりも**音声入力しやすいこと、誤認を訂正しやすいこと、中断再開、DB汚染を防ぐこと**を優先する。

## 1. 役割・2つの独立モード

**A INVENTORY**（汎用カードの所持枚数収集）

- GPTはM5-A汎用札とM5追加候補sidecar（Game8等の108種類の候補）、必要に応じM1カードマスターを照合した**実カードID確定済み候補**を、既定10件・利用者指定で5～15件ずつ提示する。
- 候補は原則としてMDでの採用頻度とN/R/SR/URの実用性、手札誘発→汎用魔法罠→EX汎用→補助/出張札の順に整理。**候補をすべて所持していると推定しない**。メニューを提示した時点ではUNKNOWN。
- 既に登録済みのカードは所持数を表示し、必要なら「そのまま/訂正」を選べる。再回答は**絶対枚数上書き**であって累積加算ではない。
- 利用者は「○○3枚、△△0枚、□□はまだ見てない」のように読み上げる。`0`は `KNOWN_ZERO`、未回答・スキップは `UNKNOWN` を維持。「持ってないと思う」は未確認なので0確定としない。
- 1発話ごと（または数件ごと）にGPTがカード名・枚数の短い確認を返すが、毎回の追加質問や長い繰り返しは避ける。バッチ終了時に総件数、未解決、スキップ、既存値との変更を確認。
- デフォルトは**チェックポイント：1ページ10件ごとにprivateステージングファイルへ保存**。接続ツールが音声会話中に使えない場合、会話中の表示記録だけを永続保存と見なさず、音声入力終了後のテキスト応答でステージング保存・読み戻しを行う。保存未成功を隠さない。
- ページカーソルは `candidate_set_version`, `ordered_card_id_list_sha`, `next_index`, `processed_ids`, `skipped_ids` を持つ。途中再開時にカード候補一覧の版が変わったらIDで突合し、名称順の変化を理由に前回の回答を飛ばさない。

**B DECK_LIST**（所持しているデッキのレシピ登録）

- ユーザーがデッキ名/バリアントを宣言し、メイン/EXを口頭で列挙。GPTは原文順を保存し、指定の区画（MAIN/EX）と枚数を紐づける。 `MAIN`/ `EXTRA` の宣言はモード区切りとして扱う。
- `「一旦ここまで」「次回続き」` は**中断/チェックポイント**、`「読み上げ終了」「このデッキは以上」` は**入力完了**。自動的なDBコミットではない。
- 読み上げ時に「モンスター」など内訳が欠けてもよいが、MAIN/EXの境界不明は要確認。デッキ枚数が40未満・60超、EX16以上でも**入力を破棄せず**エラーとして保持し、完成扱いだけを保留。デッキ種・カード効果など勝手に補完しない。
- 同じカードを複数回読んだ場合、**候補として合算**した上で原発話と重複行を保持し、3枚超/規制違反を検出。カード名の発話ゆれを別カードとして黙って登録しない。
- 所持デッキの入力は**デッキ構成の宣言**であり、所持DBの登録済み枚数への追加・更新を意味しない。同じカードが複数デッキに登場しても所持数を合算しない。カードが手持ちにあるという推定も、明示確認がない限り所持DBには書かない。
- **デッキリスト保存の専用DBテーブル・HEAD切替運用が存在するか初回に調査**する。未実装であれば独立したprivate構造化JSONスナップショットをDriveに保存し、`DECK_SAVED_PRIVATE_SNAPSHOT`と表記。本番DBへ保存したと偽らない。専用schema・正本の更新経路が検証できた後にのみ本番DB登録へ進む。
- 同じデッキの更新は `deck_id`・`version`・`supersedes` を持つ独立版とする。既存デッキの上書き・自動合算を禁止。

## 2. 音声カード名照合

`TRANSCRIBED -> NORMALIZED -> DB_LOOKUP -> RESOLVED / AMBIGUOUS / UNRESOLVED -> USER_CONFIRM -> STAGED`

- カード名は日本語の読み上げから採取し、M1のカードマスター・正式名称・ID・表記ゆれを検索する。愛称・短縮（「うらら」「泡影」等）、同音異表記、区切り、音声認識の漢字変換誤りは**候補検索**に限定し、推測だけで確定IDを割り当てない。
- 1件の確定可能候補を示せる場合は正式名称・IDへ解決する。複数なら1～3候補を簡潔に提示し、利用者の選択/再読み/テキスト入力を待つ。
- 不明な場合「『○○』と認識しましたがカードが特定できませんでした」と返し、`UNRESOLVED`で保留。**照合不能1件を理由に他の既に確定した発話を破棄しない**。一方、本番DBコミットは原則未解決を除外した承認済み確定バッチだけを対象とし、未解決を勝手に0枚や近似カードへ置き換えない。
- 一時記録には `utterance_fragment`（必要最小限）、`recognized_name`、`card_id`/null、`count`/null、`verification_status`、`source_timestamp`、`batch_id`、`corrected_from`を持つ。
- 表記ゆれ訂正は旧入力を消すのでなく訂正履歴を記録。長い音声を途中で失った場合、**最後に成功確認できたprivateチェックポイント**までしか保存済みと主張しない。

## 3. 一時保存と本番反映（M2既存経路の尊重）

1. **ステージング**：会話中の認識結果をprivate JSONとして不変バッチ化。既存 `voice_staging.parse_json/save_batch` は `batch_id`, `scope`, `entries(raw_name,owned_count)` を受け、名前から勝手にIDを生成しない。`supersedes`付き訂正と冪等な保存を利用。
2. **本人確認**：バッチ毎または登録するタイミングで、カード名/ID・枚数、登録済みの値からの変更、未解決・曖昧、0枚とUNKNOWNを並べて確認。`「次へ」`は一時保存の承認であり、本番DB更新承認と混同しない。
3. **本番反映コマンド**：利用者が `「ここまでの所持カードをDBに登録して」` 等と明示した場合のみ、本番HEADを最新再取得し、M2 `preview_inventory` で差分を提示する。
4. **最終承認**：previewを見せて明示的に承認を受け、`prepare_inventory` で候補ZIPを作る。M2が定める単一ライター・旧ZIP/HEADバックアップ・新ZIPの独立読み戻し・HEADの直前再チェック・HEAD更新後の独立読み戻しをすべて実施。Drive APIにatomic CASがないため同時書込の完全安全性は保証しない。
5. **結果照合**：成功時は `COMMITTED`、新世代、適用カードID件数、変更された枚数、ZIP/HEAD SHA、失敗0件を示す。未成功なら `STAGED` / `PREVIEWED` / `BLOCKED` / `FAILED` を区別し、元のステージングを維持。成功を確認できないとき「登録済み」と答えない。
6. **0枚の再登録**は`KNOWN_ZERO`を明示的に更新。手元未確認カードは `UNKNOWN` のまま。所持枚数の変更は絶対値でありインクリメントではない。

## 4. 個人情報・運用の注意

- 実所持台帳とデッキ構成はprivate Driveに保存。公開GitやGitHub Issue/Actionsログへカード個票/発話原文/所持数/デッキリストを送らない。
- 音声入力機能はチャットクライアントの音声認識によるテキスト化が使える場合に依存する。**リアルタイムで音声ストリームからDBへ連続書込みできることは保証しない**。利用環境でツールが使えない場合、音声終了後にテキストで確認→保存する。
- ChatGPT会話ログだけを耐障害の一時DBと見なさない。実際に保存し、再取得確認したprivateチェックポイントだけを永続化済みとする。
- 一度に読ませる候補数は調整可能。混乱を避けるため連続発話の既定上限は10～15件程度、長いデッキリストは10件程度で短い確認区切りを入れる。
- 既存`voice_staging`のreadmeには旧のP1-A1未実装状況の履歴がある。実際の現行HEADと運用範囲をその都度確認し、履歴文のNO-GOを現在の絶対状態とみなさない。

## 5. 受入試験（構想。今回コード実装ではない）

1. 既知登録3枚→読み直し3枚で差分0。既知3枚→読み直し0枚で`KNOWN_ZERO`の訂正プレビュー。
2. 10件のうち2件スキップ→8件ステージング、2件UNKNOWN保持、次回同じカードを再出題できる。
3. 不明な発話1件→他の9件を保持し、不明名だけ確認。カードID推定補完禁止。
4. 2ページ20件→ページ2終了で保存→次回ページ3から再開。カード一覧並び替えが発生してもID基準で突合。
5. 「読み上げ終了」→整形案表示。**「DB登録して」ではない限り本番更新しない**。
6. デッキAとデッキBに同じ汎用カード3枚ずつ→在庫6枚に加算しない。
7. MAIN 41 / EX 16→入力保持・EX超過警告、完成扱い・本番保存は保留。
8. 音声中のツール利用不可→text checkpoint後にprivate保存した範囲だけ「保存済み」と報告。
9. 更新承認後、HEAD世代が変わっていた→更新を停止して再プレビュー。旧HEADを上書きしない。
