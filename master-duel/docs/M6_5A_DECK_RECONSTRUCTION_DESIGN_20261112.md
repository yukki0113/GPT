# M6-5A デッキ再構築ロジック — 教師依存からの脱却（2026-11-12）

## 本来のプロジェクト目的

本プロジェクトは、ネット上にあるURを大量に含む完成済み教師デッキを再現するためではない。**テーマを希望する利用者の実所持カードと制約（例：新規UR0、SR以下、所持済みURのみ）を出発点に、カード正本DB、汎用所持台帳、出張所持リストを検索し、MAIN・EXを相互に調整して対戦可能性のある構築案を考える**仕組みである。

教師デッキはテーマ理解と役割・展開ルートの出典の一つにすぎない。教師の未所持URを除外しただけの40枚/EX7枚を「完成」としない。カードDBの検索は原則private正本を優先し、Webを毎回検索する仕組みにしない。AIが推論するカード相性は、本文・必要素材・発動条件・ロック・関連出張の依存カードで独立照合できなければ候補のまま。

## 1. 構築の順序（AIの推論ワークフロー）

1. **依頼と制約を固定する**：ユーザー明示条件を優先し、既定LOW_RARITY_COREは必須テーマCORE UR0＋新規UR生成0。所持汎用URは利用可能。厳格な全UR0はSTRICT_NO_UR指示のときのみ。SR以下指定は「テーマ中核をSR以下」と「全MAIN/EXをSR以下」のどちらかを明示して解釈する。CPは各通貨独立。
2. **教師の構造を理解する**：役割、初動、展開、到達盤面、必須中核、勝ち筋、EX素材条件を分離。記事のURがあるからCORE必須とはしない。
3. **テーマ全体をDB検索する**：教師リストにないN/R/SR（必要に応じて所持UR）の全テーマ候補を検索。文字列一致は正式テーマ所属の証明ではなく、本文/効果と照合する。
4. **UR除外による機能損失を分析する**：初動・展開・妨害・除去・フィニッシャー・継戦・EX素材と必要パーツにどう影響するか。単なる1:1置換に限定しない。
5. **低レアテーマ内で再設計する**：下位レアテーマモンスターの増量、別展開、別の勝ち筋。例えば海晶乙女のR主体運用可能性を、展開ルートと合わせて検討。
6. **共有性を使って外へ探索する**：種族、属性、レベル/ランク、相互サポート/コスト/特殊召喚条件を元DBで検索。同じ種族・属性・レベルだけでは相性確定でない。純テーマ、テーマ＋出張、混合再設計の三系統を比較し、元テーマがほぼ消える場合は依頼意図から逸脱することを明示。
7. **所有済み出張ギミックを検討する**：デモンスミス等の必要MAIN/EX・枚数・所有数、出張のロックと他初動の競合、前提パーツ不足、追加CPの有無を確認。M5-A旧索引はGeneration3由来の候補で現行Gen5と異なるため本文・規制再照合前は暫定。
8. **EXを素材から逆引きして設計する**：レベル4を安定して並べるなら汎用ランク4、カード名の異なる2体なら汎用LINK2、テーマ内EXを増量できるかを探索。EXは原則15枠の有効活用を目指す。15未満は**探索済み・使える候補と採用見送り理由の明示**が必要。単に教師EXのURを抜いて7枚だから完成とはしない。EXのホープ出張のようにMAIN必要カードが発生したらMAINに戻る。
9. **MAIN/EXを往復して調整する**：EX採用に必要なMAIN札の追加、通常召喚権・初動・事故札・ロック、主力テーマの密度と勝ち筋を再検査。相性未確認の候補を勝手に埋めない。
10. **最後に汎用所持台帳でデッキを締める**：灰流うらら・無限泡影等は**現在の所持枚数**を上限として優先検索し、妨害、除去、後攻突破、誘発耐性を必要に応じて配分。所有0/未登録UNKNOWNを持っていると扱わない。テーマ初動を圧迫しないことを検査。これは「余った枠に昔の低レア汎用札を機械的に詰める」のではなく、実所持済みで不足する役割を満たす工程。
11. **最後に評価・比較する**：MAIN40–60、EX0–15/3枚上限、独立した3種類のUR条件、現行禁止制限、所持・各通貨CP範囲、未検証効果、採用理由、失った動き、将来強化案を比較。未確認は禁止制限PASSにもGAME_TESTEDにも昇格させない。

## 2. 探索打ち切りゲート

最低限以下の検索実行証跡を必要とする。

- `THEME_INTERNAL_LOW_RARITY`：教師外のテーマN/R/SRを検索した。
- `RACE_ATTRIBUTE_LEVEL_CROSS_THEME`：主力レベル・種族・属性の連携可能性を、効果・制約根拠と分けて検討した。
- `OWNED_ENGINE_AND_GENERIC`：所持出張・汎用パッケージの使用可能性を検討した。
- `EXTRA_FROM_AVAILABLE_MATERIALS`：召喚可能素材からテーマ内/汎用EXを逆検索。EXが少ない場合は別の候補も調べる。
- `MAIN_EXTRA_ITERATION`：EXルートからMAIN必要札へ戻って差分を検討した。
- `OWNED_GENERIC_FINISH`：**登録済み所持枚数に応じた汎用札を検索**して役割別に検討した。
- `FINAL_COST_AND_LEGALITY_REVIEW`：使えると断定できないカードは保留し、所持UNKNOWN・CP・M3候補未検証を残す。
- 純テーマ / テーマ＋出張 / 混合の3構築系統の可能性・棄却理由を明示する。

探索の証拠は「何を検索し、候補が何枚あり、何を採否して、なぜか」であり、推論しただけのカード名羅列では不可。探索済みでカードが出ない場合は0件をそのまま記録する。**未検索の0件扱いは禁止**。

## 3. 現実的な設計境界

- `discovery.py`：SHApinの原本SQLiteを読取専用で検索する基礎。テーマ名、属性、種族、レベル、ランク4/リンク2等、レアリティ、所有済みか否かで絞る。文字列や属性の一致は相性・公式所属・合法性を証明しない。
- `reasoning.py`：M6-3構造候補＋M6-4評価へ「9探索レーン」の計画・チェックゲートを追加する。検討証跡なしではBLOCKED、全検索レーン終了後もGAME_TESTEDを証明せずREVIEW_REQUIREDに留まる。
- **本段階ではカード本文の正確な効果論証、融合/シンクロを含むEX全体の自動検索、テーマ間ギミックの組立、所持済み汎用でMAINを自動再配分する完全探索アルゴリズムは未完成**。設計と初期探索・ゲートが動いたという範囲に限定する。次のM6-5B/Cでは候補ランキングとMAIN・EXの再組立を実装し、実カードの効果・召喚条件・ロックと合わせて検証する。
- M6-6 private統合試験は、構築品質の検査を満たした後に実施する。従前の「M6-5の候補をそのまま統合すれば完成」の工程順は改訂する。

## 4. 軍貫EX7の失敗事例を受入テストにする

- 軍貫のN/Rや既存低レアテーマEXを洗い直す。
- レベル4から汎用ランク4、モンスター2体から汎用LINK2を探索。
- 余りEX8枠は必ず探索結果・棄却理由の証拠を残す。
- ホープ出張などMAINに追加パーツが必要な場合は、EXだけでなくMAINを再検討。別の勝ち筋が成立しなければ採用しない。
- 適合した汎用札（うらら/泡影など）の所有枚数を現在HEADから取得してMAINを調整。
- レシピ完成は構造PASSだけでは不可。探索不足の候補はBLOCKED、検索済みで相性未確定はREVIEW_REQUIRED。妥当な最終構築の判断は外部のカード本文・展開検証と別途受入が必要。
