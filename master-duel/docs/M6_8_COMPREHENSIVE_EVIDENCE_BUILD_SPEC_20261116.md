# MDデッキ構築ロジック 総合再設計 v2（M6-8、2026-11-16）

## 0. 基本方針と固定の受入条件

本書は2026-11-10の標準構築手順、2026-11-16までの軍貫リプレイ、EX15枚、Game8採用方針、役割固定減点の撤廃、所持DB全件監査を統合した**次回構築の事前仕様**。結果を見てから個々の採点を後付け変更して合格とすることを禁止する。

**目標**：所持・新規UR0・MD禁止制限・デッキの実現可能性を守った、説明可能なMAIN40（必要なら40〜60）／EX最大15。EX使用可能なら15枚を積極的に目指す。実戦の勝率は測定しなければ不明。未完成案・仮説・対戦検証済みを混同しない。

## 1. 順序と責務

| 順序 | 入力・出力 | 絶対条件 |
|---|---|---|
| 1 | 要求・モード | 「UR0」は**新規UR生成0**、所持UR使用可。厳格UR0は明示指定時のみ |
| 2 | Drive最新HEAD→ZIP→SQLite/SHA | 所持を**全登録分**照合。KNOWN_ZERO / KNOWN_POSITIVE / UNKNOWNを分離 |
| 3 | MDレア・規制・CP | MD用の現行日付付きカードID別上限が全候補に必要。M3未検証値・OCG/TCGの転用は禁止 |
| 4 | テーマ本体と最小ギミック | 出典・枚数根拠・初動・展開・ロック・必要EXをレビュー。根拠のない「テーマXX枚」固定比率は禁止 |
| 5 | 候補発見 | M5、全所持MAIN、汎用・属性/種族・ランク/リンク、必要ならWeb。発見だけでは採用可の証明ではない |
| 6 | 事前の**評価ポリシー** | 各カードのGame8等の汎用性、デッキ適合性、1枚目〜3枚目の価値、全出典を**構築前に凍結** |
| 7 | MAIN構築 | テーマ最小必須枚数を確保し、残りをカード別・枚数別スコアで比較。同じ「妨害」役が多いだけでは減点しない |
| 8 | EX構築 | テーマ→主力方式の汎用→他方式→追加発見の順に検索。検索順は採用優先の絶対順でない。素材・ロック・所持・規制のゲート |
| 9 | 監査 | MAIN/EX全カードおよび**登録済み所持全件**の採用/不採用/要確認、カード別1〜3枚目根拠、UR/CP、規制、EX不足、未評価候補 |
| 10 | 出力 | 実装上のPASS、資料不足REVIEW_REQUIRED、禁止・欠品・SHA不一致BLOCKEDを区別。凍結入力のSHAと実装commitを保存 |

## 2. Game8評価の扱い：積極利用、過大解釈禁止

Game8の汎用カード一覧 <https://game8.jp/yugioh-masterduel/423814> はSS/S/A/Bを**入手優先度・汎用性**として掲載する。2026-08-03付の掲載基準で、SSは高い汎用性、Sは系列内で優秀、A/Bはデッキ・環境により採用機会がある。Game8に未掲載であることは「弱い」の証明ではない。

v2ではGame8のtierを**基本採用価値の事前事実に基づくprior**として使用する。下表の数値は**本プロジェクト側が先に決めた採点換算**であり、Game8自身が公表した点数でも、統計的採用率でもない。

| Game8参照 | M6-8ベース点 | 扱い |
|---|---:|---|
| SS | 90 | 強い汎用性を出発点に置く。禁止なら規制ゲートで排除 |
| S | 80 | 同上 |
| A | 70 | 同上 |
| B | 60 | 同上 |
| NOT_LISTED | **独立した根拠付き0〜100** | 未掲載を0点にしない。別途効果・構築・環境の評価が必要 |

**カード別の例外**：そのデッキで本当に扱いにくいなら `deck_adjustment`（-60〜+20）で調整し、`deck_reason`と根拠を必須にする。tier付きで `APPLICABLE` の場合、大幅引き下げ（-15未満）は拒否。大幅引き下げには `CONSTRAINED` と効果ロック・発動条件・特定マッチアップなどの独立証拠 `CONSTRAINT:` / `MATCHUP:` / `LOCK:` / `CARD_TEXT:` が必要。`NOT_APPLICABLE`なら採用上限0。低レア・所持・高レアというだけでゲーム上の性能を低く見積もらない。

**規制は別の硬いゲート**。Game8に掲載された高評価カードでも、MD禁止なら0。古いページの記載は規制の証明にはならない。

## 3. 採用枚数の価値は独立に審査

Game8の構築解説 <https://game8.jp/yugioh-masterduel/426127> は、初動・積極的に引きたい札を3枚、複数引くと弱い札を2枚、サーチ容易／引きたくない／ピンポイントの札を1枚にする基準を示している。これは判断材料であり、カードごと・テーマごとの確証ではない。

v2は各カードに`recommended_max`、`quantity_reason`、`copy_adjustments[3]`、`copy_reasons[3]`を必須にする。n枚目の得点は以下（clamp 0..100）。

`score(card,n) = clamp(tier_prior_or_reviewed_general_value + reviewed_deck_adjustment + reviewed_copy_adjustment[n])`

- 1枚目も2枚目も3枚目も**それぞれ別の得点・根拠**を持つ。
- 同名多枚採用を一律に減点しない。実際の初手需要・ダブりの有用性・サーチ・複数同時使用制約を個別に審査する。
- `recommended_max`は単なる強制3枚ではなく、カード個別のレビュー上限。規制、所持数、URモード、注釈最大枚数などの硬い制約より優先しない。
- 他の「妨害札」が既に何枚あるかを点数に掛けない。役割分布は診断情報としてのみ残す。
- 機械的な40枚の穴埋めによる低証拠採用は監査対象。新規UR0のために性能の弱いカードを強いと偽装しない。

## 4. アルゴリズムの詳細と正直な限界

- 現行の`recompose_portfolio`は選定値の高いカードを1枚ずつ追加する**決定的な逐次構築**。v2が採用するn枚目の値は根拠付きの個別値。完全なデッキ全体の組合せ最適化、初手確率シミュレーション、プレイングテストではない。
- テーマ最低枚数は、カード効果・既存レシピ・展開ルートの調査で入力者が決める。ソース未検証なら仮説として監査に残す。
- 出張ギミックは必要部品を一括で判定。独立評価で上限0になった部品を強制採用しない。
- EXはPOSSIBLE_ON_PAPERの軽量素材スクリーンのみを採用し、15枚不足時は`EX_SLOTS_UNFILLED_RESEARCH_REQUIRED`。同名2枚目の一律減点なし。実際の同時展開や特殊召喚ロックは別検証。
- 強い同役割カードを11枚以上採用すること自体は減点原因ではない。ただしMAIN総枠と初動/展開成立の条件は守る。
- テーマ・主力方式・他方式は**検索順**であり、採用候補の固定点数差ではない。以前の`24 × 段階`の数値補正は廃止し、評価点が同じ場合のみ探索段階を同点決着の参考にする。

## 5. v2の機械的契約

- policy schema: `md-m6-8-evidence-build-policy-v2`。
- MASTER SQLite SHAと`as_of`を一致させる。評価に使うGame8 URLと確認日、カードIDの`DB:<card_id>`根拠が必須。
- tier付きカードは原則`general_value=null`（tierと評価の二重取りを禁止）。未掲載はtier点を付けず`general_value`を独立レビュー。
- 評価に使う`assessment_status`はTEXT_CHECKED/HUMAN_REVIEWED/GAME_TESTEDに限定。単なる検索ヒットやUNVERIFIED_SOURCEは採用評価に昇格させない。
- v2の全注釈カードは完全に評価済みでなければ構築拒否。必要なテーマminimumがカード別`recommended_max`を超えたら拒否。出張必須部品、混合のクロステーマカードも同じ。
- `decision_policy_sha256`は凍結入力をカノニカルJSONでSHA-256化した値。**結果を見た後の入力変更は別SHA・別試験**。
- 古い`md-m6-7-decision-policy-v1`は履歴の互換実行にのみ残し、新規`integrate_private_deck`では`EVIDENCE_COPY_BUILD_POLICY_V2_REQUIRED`で拒否。
- 規制ゲートは`md-m6-7-regulation-gate-v1`を引き続き要求。日時・MD専用・候補全件・出典確認、出典不足はfail-closed。
- 全所持MAIN候補の未注釈・未評価を報告。候補検出と正式採用を混同しない。

## 6. 再評価・受入の設計（後出し禁止）

**実装ゲート（合成）**：
1. SS90/S80/A70/B60のtier priorを再現。未掲載を0点にしない。
2. tierの無根拠な大幅引下げを拒否。出典・ID・確認日・効果制約の証拠を要求。
3. 1枚目〜3枚目は個別得点と採用理由。役割/グループの固定減点ゼロ。
4. MAIN40/EX15を目指し、素材・制約・MD規制・所持・新規UR0ゲートを尊重。
5. 未評価、SHA不一致、強制的な出張カード採用を拒否。
6. 採用・不採用・所持全件の監査にtierと枚数根拠、凍結入力SHAを含める。

**実データゲート（別）**：
1. 非公開Gen6の本番HEAD/所持全件・Game8評価台帳を更新日時付きで取得。
2. **生成結果を見る前に**カード別のreview済み適合性・1〜3枚目理由を作成し、SHAで凍結。
3. MDの現行規制について候補全件のカードID別上限・一次情報を確認。未知は法的適合PASSを宣言しない。
4. v2で軍貫を再生成し、既存のGen6レシピと比較する。SS《増殖するG》を含む高評価カードが選外なら、**事前の個別制約理由・点数・所持・枠競争**のどれが原因か出力する。結果を見て調整する場合は新規ポリシーとして別版にし、旧版は保存。
5. テーマの初動・EX展開の実演/対戦評価が無ければ、構築案にREVIEW_REQUIREDを残す。

## 7. この変更で完了していないこと

- 最新のMD全候補を網羅した**ゲーム内・公式確認済み規制ポリシー**の作成。
- Gen6に紐づくM5-C教師・ルート資料の正規再発行。
- Game8のSS/S/A/Bを公式API的に抽出・カードIDと自動更新する処理。現状はレビュー済み入力を要求する。
- 全所持・候補カードについてデッキ固有の適合性と枚数根拠を**自動生成して正しいと証明**する仕組み。
- 初動確率・盤面・対戦勝率の検証。
- Game8 prior（90/80/70/60）の数値的妥当性の統計検証と、EX検索段階の同点時決着の経験的評価。

これらが未達の限り、合成テストPASSだけで「軍貫の最適構築完成」と宣言してはならない。
