# M6-7 競争評価型デッキ構築ロジック — 2026-11-12

## 問題と修正

旧M6-5Cは、MAINの大部分を固定優先度、役割不足数、所持による補正で埋め、EXは素材テキストが「紙面上可能」なら優先度順に上限まで詰めた。これは**素材が出せること**と**そのカードを採用する価値があること**を混同する。テーマ外の流行札が検索対象に存在しなければ、比較自体を実施せずに旧い所持汎用札を補充してしまう。

この是正は「特定カードの優遇」ではなく、共通評価・比較・根拠の強制で行う。

1. `engine_m6/decision_policy.py` は**非公開DBのSHA**、評価日、必ず検索するカードの名前、カード別の証拠付き評価を契約化する。汎用性能・環境適性・テーマ適性・即効性・資源効率・役割必要性の6軸を各0〜5で評価する。値は日付付き・根拠付きの判断入力であって、モデルが知らないゲームルールを機械的に創作しない。
2. `recompose_portfolio(...,decision_policy=...)` は新しい評価が提供された場合、旧来の固定28枚テーマ優先ルールに依存せず、同じ競合グループ・役割の採用数に応じた限界効用逓減を使う。所有している事実は使用可能な枚数制約であって**性能加点にはしない**。採用見送りの比較理由をsource-rooted candidateごとに記録する。
3. EXTRAは既存の素材判定が`POSSIBLE_ON_PAPER`であることに加え、個別の条件・ロック点検、証拠付き役割評価、最低の採用価値スコアを要求する。該当しないカードで15枠を埋めない。Xとリンクを同時に比較し、ランク4が出せる盤面でも**同名2体では「異なる名前2体」要求のリンクを出せない**ことを維持する。紙面上の素材の一致はゲーム内での召喚成功の証拠ではない。
4. `integrate_private_deck` は新たな実データ構築時に `decision_policy` を**必須**とし、旧方式への暗黙のフォールバックを禁止する。評価対象名は、教師デッキに出てこなくても現行DBのMAIN/EX双方で自動検索する。レベル4を2体用意できる仮説/検証済み盤面があれば、ランク4とリンク2を独立検索する（DBでLINK値がNULLの候補は別途ID・原文確認を要する）。
5. `policy_assessment_gaps` / `required_name_gaps` / `policy_source_gaps` を明示し、未発見カードや未評価カードを「相性が悪いため不採用」と誤説明しない。`competitive_candidate_comparisons`で不採用・要確認・採用の根拠を残す。選定理由は候補本体へ転記され、private完全レシピ出力に反映される。

## 実データの契約

非公開の評価入力例として、`required_review_names`には、その時点で比較すべき環境札・対策札を**カードDBの正式名で**列挙する。軍貫の受入では、少なくともユーザーから指摘された「マルチャミー・フワロス」「三戦の才」「禁じられた一滴」、既存の手札誘発、除去・後攻札などの比較を検討対象に含める。これはこれらを**必ず採用する**指示ではない。現行MDの存在、採用可能枚数、効果・コスト、所持・CPはそれぞれ別に検証する。新規UR0では未所持URを候補検索から消さず、性能評価と**制約上不採用**を区別する。

主要API:
- `validate_decision_policy(policy,master_sha256=...)`: 評価契約の検証。
- `recompose_portfolio(...,decision_policy=policy)`: 比較評価に従って再構築し、採否理由とカバレッジを返す。
- `integrate_private_deck(...,decision_policy=policy)`: SHAピンしたprivateソース、M6-1→M6-5からM6-7レシピ出力の正式入口。評価入力がなければfail closed。
- `engine_m6/tests/test_m6_7_competitive.py`, `test_m6_7_rank_link.py`: 合成データで固定優先度より競争評価が優先すること、弱いEXで空き枠を埋めないこと、未検索環境札の検出、ランク4とリンク2の異なる素材条件を検証するための回帰。
