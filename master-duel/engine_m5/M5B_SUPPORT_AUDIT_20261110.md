# M5-B — 横断テーマ候補／属性・種族サポート検索（2026-11-10）

## 判断

利用者の指摘を受け、M5-Aの3テーマ・汎用5種類だけではM6の「広く低レアテーマを発掘する」目的を達成できないため、M5-Bの横断候補索引を追加する。個別テーマパックの拡大だけでなく、**カード効果から条件付き支援を取り出し、サポート元カードから属性・種族の対象候補を検索する**設計とする。

### 確認済みのローカル・実データ監査

- 入力は非公開Drive世代3本番SQLite（13,948枚）とM4効果索引75,913件。SHA256それぞれ `42fa57c5a41e9d41ae7ae064450485d1b18109f45a616528abff9025cd43b654`、`9312109612b1ad38ec318a7c5d6745c9b82c97dc872613a2994a98d19c738451`。両者は読み取り専用で処理。
- M4の `role=ACTION` のみを支援処理候補の入力とし、`REFERENCED/CONDITION` を支援と誤分類しない。`SEARCH_FROM_DECK`、`SPECIAL_SUMMON` 等の動作を中心に日本語の属性7種・種族25種を認識。
- 索引実測値：カード13,948枚、**属性・種族支援に関する原文根拠付き候補2,288件**、**名称グループ候補580件**、名称グループ所属候補6,716件、名指し参照候補7,785件。
- 名称グループとは、カード本文の `「名称」` の候補であり、**名称を含むカード2種類以上と参照文のあるもの**に限定。これを公式テーマ/アーキタイプの正規IDと混同しない。「青眼の白龍」等の個別カード名を指定する効果や部分名称・通称も混在する。
- 属性・種族の候補とは、M4の効果動作と同一文に属性・種族指定があるという意味で、正確な対象条件や裁定を証明しない。対象カードから属性／種族の候補支援を逆引きでき、`match_mode='ALL'` は**同じ効果文区間**に両条件がある候補に限る。
- 索引はprivate SQLiteサイドカーであり、公開GitHubには原文・カード個票を含めない。**本番DB・M4索引・M5-A索引・所持・禁止制限はいずれも不変更。**
- 効果対象がコスト・相手カード・別効果の参照である場合の誤推論は完全には排除できないため `UNVERIFIED_SUPPORT_CANDIDATES` を維持。候補検索の空結果は「不可能」の証明ではない。

## 技術的境界・受入

- module `engine_m5/support.py`、public合成テスト `engine_m5/tests/test_support.py`。入力ハッシュ固定、破損検査、別SQLiteへの原子的保存、上書き拒否、効果原文オフセットとSHA維持、属性・種族フィルタ、対象カード逆引き、AND検索、名称グループ候補一覧と外部からの名指し候補を実装。
- 自動で具体的な実際のデッキを組めるか、公式のテーマ所属、特殊な裁定、出張エンジン相性、生成CP/禁止制限には**直結させない**。M6の候補選抜時にM4原文→M3規制→所持→UR条件を再検証する。
- **M6前の残りの品質ゲート**：低コストテーマを最低数種類、異なる属性・種族から抽出して人手で根拠と構成をレビューする。580名称候補を580のデッキ案とみなさない。false-positive分析を対象カード群から実施する。
- GitHub CI、private Drive sidecarの保存・独立読戻しの結果を後続追記する。
