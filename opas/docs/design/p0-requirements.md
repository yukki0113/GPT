# OPAS P0画面要件 v0.2

更新日: 2026-10-09

現時点の実機証拠とユーザー一次情報から定義するP0要件。予約確定・取消など実環境の状態変更は行わず、確認可能な範囲で設計を確定する。

## P0-1 ログイン前トップ

### 目的
スマートフォン利用者が、主要タスクであるログインまたは空き状況照会へ短距離で到達できること。

### 要件

- ログイン導線をファーストビュー、または極めて短いスクロールで到達可能にする。
- 「ログイン」「空き状況照会」を主要CTAとして明確に区別する。
- お知らせは全件本文をトップに展開せず、重要度・日付・カテゴリを用いた要約表示を基本とする。
- 緊急・期限付きのお知らせは主要CTAを妨げず視認できる形で提示する。
- 「すべてのお知らせを見る」導線を用意する。
- 長大ページ対策を「ページ末尾へ」だけに依存しない。

## P0-2 利用者登録更新案内

### 目的
更新期限が近い利用者が、期限・影響・必要手続き・次の行動を迷わず理解できること。

### 要件

- 期限を明示する。
- 未対応時の影響を明示する。
- 必要な手続き、対象窓口、必要物、所要期間、受付条件を一連の情報として整理する。
- 詳細説明または手続き案内への明確なCTAを設ける。
- オンライン化の可否は制度・契約調査が完了するまで断定しない。

## P0-3 ログイン後ナビゲーション

### 目的
頻度の高い予約・照会操作へ迅速に到達できること。

### 要件

- 「空き照会・予約」「予約照会・取消」を主要操作として優先表示する。
- 抽選、利用者設定、その他照会は意味のある単位でグルーピングする。
- 全機能を同じ視覚重量の大型カードで単純縦列する設計を再検討する。
- ログアウトは利用可能であることを維持しつつ、主要タスクより強く目立たせない。

## P0-4 空き照会・予約

### 確認済み仕様

- 照会方法 → 大分類 → 小分類 → 施設選択 → 空き状況の多段フローがある。
- 施設は複数選択可能。
- 空き状況は日付×時間帯の表形式。
- 施設選択表・空き状況表ともスマホ画面幅を超える。
- 同一日の複数時間帯は選択可能。
- 異なる利用日の同時申込は不可。
- 選択後は申込内容入力へ進み、施設・日付・時間帯・面数を確認し、利用人数等を入力する。

### 要件

- 横スクロールを前提としない。
- スマホでは日付単位または施設単位のカード／リスト表示を優先する。
- 空き／満員／休止等の状態を文字・記号だけに依存せず分かりやすく示す。
- 同一日内の複数時間帯をまとめて選択できる現行能力は維持する。
- 複数日同時申込不可の制約は、エラー後に知らせるだけでなく選択前または選択時に明示する。
- 施設・競技・日付の絞り込み条件を画面上で常に把握できるようにする。
- よく使う条件を短距離で再利用できる導線を設ける。
- タッチ対象を十分な大きさにする。

## P0-5 申込内容入力

### 要件

- 選択した施設・日付・時間帯・面数を簡潔な予約サマリーとして表示する。
- 入力が必要な項目と確認のみの項目を視覚的に分離する。
- 必須項目を明示する。
- モバイルでは縦長になりすぎないよう、補助機能（お気に入り登録等）は主入力より視覚優先度を下げる。
- 最終的な予約確定前の重要確認は維持する。
