# OPAS To-Be設計 — 抽選申込 v0.1

更新日: 2026-10-15

## 目的

現行の抽選申込で確認した以下の課題を、制度・業務ルールを原則維持したまま改善する。

- 「利用目的から絞り込む」経路では毎月同じ条件選択を繰り返しやすい。一方、現行にも「施設を選択する」「お気に入りの施設で照会する」入口が存在する
- 横長表がスマホ幅を超過する
- 複数区分不可・申込上限が後出しエラー
- 1件申込後に再び入口から繰り返す

## To-Be主要フロー

```text
TB-LOT-01 抽選申込トップ
  ↓ いつもの条件で申し込む
TB-LOT-02 条件サマリー
  ↓
TB-LOT-03 抽選対象選択
  ↓ 1日時・1区分
TB-LOT-04 申込内容確認
  ↓
TB-LOT-05 完了
  ├─ 同じ条件で別日
  ├─ 同じ日で別施設
  └─ 終了
```

現行の照会方法選択には「利用目的から絞り込む」「施設を選択する」「お気に入りの施設で照会する」の3経路がある。お気に入りは施設とジャンル（種目）まで固定されており、実利用では定型申込の主要ショートカットとして使われている。To-Beではこの既存導線を新設扱いせず、最上位の主要導線として前面化・短距離化する。

「施設を選択する」は、種目を問わず約40〜50施設が縦に並ぶ一覧から施設を選び、その後に利用目的（種目）を選択してカレンダーへ進むため、定型利用の主要導線にはしない。機能としては残すが、補助導線として扱う。

## 主要要件

### TB-LOT-01 抽選申込トップ
- 現行の「お気に入りの施設で照会する」を活かし、「いつもの条件」を主要CTA化。お気に入りは施設とジャンル（種目）まで固定されており、実利用でも高頻度で使われている
- 受付期間、申込件数、残申込可能数を表示
- 条件変更は副CTA

### TB-LOT-03 抽選対象選択
- 横長表を廃止し、日付単位の縦カードへ
- 時間帯は単一選択UI
- 複数区分エラーをUI構造で防止
- 残申込数0は選択不可
- 「時間帯任意」を明示的な選択肢として扱う

### TB-LOT-04 申込内容確認
- 1申込=1カード
- 施設、日付、時間帯、面数、ジャンル、申込回数への影響を表示
- 最終確定は維持

### TB-LOT-05 完了
- 条件を保持したまま次の申込へ
- 「同じ条件で別日」「同じ日で別施設」を提供

## As-Is → To-Be

As-Is:
照会方法選択（利用目的から絞り込む / 施設を選択する / お気に入りの施設で照会する）
→ 選択した経路に応じた条件指定
→ 横長表
→ エラーで制約通知
→ 確認
→ 完了

To-Be:
いつもの条件 → 日付/時間帯 → 確認 → 完了 → 次の申込

- 複数区分選択エラー0
- 上限超過エラー0（事前防止/警告）
