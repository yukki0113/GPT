# OPAS ログイン前トップ To-Be仕様 v0.1

更新日: 2026-10-16
用途: ログイン前トップのスマホ向け改善案を、後続GPT/Codexが画像解析なしで理解・再現するための正本仕様

## 1. As-Isで確認済みの課題

- iPhone 16で初期表示からログイン欄まで約13スクロール。
- 初期表示の大部分を長い「お知らせ」本文が占有する。
- `ページの最後へ▼` はあるが、利用者の目的である「ログインへ」を直接示すCTAではない。
- ログイン欄の下に、ログイン不要の照会機能が配置されている。
- `利用者登録の更新について` 等、重要なお知らせと一般告知が同じ長文領域に並ぶ。

## 2. To-Beの設計目標

- ログイン利用者がファーストビューから1操作以内でログインフォームへ到達できる。
- ログイン不要の空き状況照会もファーストビューから開始できる。
- 重要なお知らせは見落とさせないが、全文を主要導線の前に展開しない。
- 通常のお知らせは要約・折りたたみ・一覧化する。
- スマホ1カラムで横スクロールを発生させない。

## 3. 画面構成

### TB-LOGIN-01 ファーストビュー

表示優先順位:
1. OPASロゴ/サービス名
2. `ログイン` 主要CTA
3. `空き状況を確認する` 副CTA
4. 重要なお知らせサマリー
5. その他メニュー

ファーストビューの目的は『何をしに来たか』を最初に選べること。

推奨CTA:
- `ログインする`
- `空き状況を確認する`

補助:
- `抽選対象日の案内`
- `当選確率の案内`
- `抽選結果の確認（未登録者）`

### TB-LOGIN-02 ログインフォーム

表示:
- 利用者番号
- パスワード
- ログイン
- ログインに関する注意事項へのリンク

ファーストビュー内にフォームを直接置く案、または `ログインする` 押下で同一ページ内アンカー/展開する案の2案を許容。

最優先は13スクロールを0〜1スクロール相当へ短縮すること。

### TB-LOGIN-03 重要なお知らせ

重要度で分類する。

例:
- 更新期限
- システム停止
- 利用条件変更

表示形式:
- タイトル
- 1〜2行要約
- 対象者/期限
- `詳しく見る`

長文全文は折りたたみまたは詳細画面へ。

重要通知はログイン導線より上に全文を挿入しない。

### TB-LOGIN-04 通常のお知らせ

表示:
- 日付
- タイトル
- 短い要約
- 詳細

最新数件のみ表示し、残りは `お知らせ一覧` へ。

## 4. ログイン後の更新期限通知との関係

実機では、更新期限対象者にログイン後 `利用者更新期限のお知らせ` が挟まることを確認済み。

To-Beではこの仕組みを維持候補とする。ただし、ログイン前にも対象者全員へ長文を読ませる設計にはしない。

ログイン前:
- 一般的な更新案内は短く要約

ログイン後:
- 対象者にのみ個別の期限通知

という役割分担を基本案とする。

## 5. 情報アーキテクチャ

推奨順:
```text
OPAS
↓
ログインする
空き状況を確認する
↓
重要なお知らせ（要約）
↓
ログイン不要の各種照会
↓
通常のお知らせ
↓
ヘルプ/利用案内
```

現行のように『全お知らせ本文 → ログイン』とはしない。

## 6. As-Is → To-Be

As-Is:
```text
トップ
→ 長いお知らせ群
→ 約13スクロール
→ ログイン
```

To-Be:
```text
トップ
→ ログイン / 空き状況照会
→ 必要に応じてお知らせ詳細
```

## 7. 評価指標

- 初期表示からログイン開始までのスクロール回数
- 初期表示から空き状況照会開始までの操作数
- 重要通知の見落とし率
- 通常お知らせ閲覧率
- ファーストビュー内CTAの理解度

目標:
- ログイン開始まで0〜1スクロール
- 空き状況照会開始まで1タップ
- 横スクロール0

## 8. 非対象

- 認証方式そのものの変更
- ID/パスワード仕様変更
- 会員更新制度そのものの変更
- お知らせ配信基盤の変更

## 9. GPT/Codex向け注意

- `ページの最後へ` が存在することを『ログイン導線が十分』とは評価しない。
- `利用者更新期限のお知らせ` はログイン後の対象者向け通知として確認済み。
- オンライン会員更新機能の存在/不存在は、この画面だけから断定しない。
- To-Beの本質は、情報削除ではなく『主要タスクを先に出し、お知らせ全文を後ろへ再配置する』こと。
