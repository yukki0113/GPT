競艇・直前情報取得 定型作業（Chatスレッド運用用）

対象となる依頼
----------------
「mm/dd ○○（会場）xxR の直前情報を取得してください」

この依頼で扱う直前情報は、BOAT RACE公式サイトの出走表に加え、レース直前に掲載される展示・水面気象を含む。
事前予想仕様書 Ver.1.2.1 の事前予想では展示・直前気象を使用禁止としているため、この取得結果を事前予想の根拠へ混在させない。

入力の解釈
------------
1. mm/dd は依頼時点の年を補って対象日へ正規化する。
2. 会場名または公式会場コードを使用する。
3. xxR は1〜12の整数へ正規化する。
4. 対象は指定された1レースのみ。
5. 結果、払戻、オッズ、予想サイト、SNS、結果を示唆する検索結果は取得・参照しない。

標準実行経路
--------------
今後のChat運用では、GitHub Issueを標準の実行要求経路とする。

Chatから workflow_dispatch を直接起動できることを前提としない。
従来の .github/workflows/boatrace_pre_race_manual.yml は手動実行用の補助経路として残す。

Issue title:

[BOATRACE_PRE_RACE_REQUEST] <request_id>

Issue body は raw JSON とする。

例:

{
  "date": "20260825",
  "venue": "三国",
  "race": 4,
  "format": "json"
}

Workflow:

.github/workflows/boatrace_pre_race_issue.yml

Issue Workflow側の処理
-----------------------
1. Issue title prefix と request_id を検証する。
2. Issue body を json.loads() で解析する。
3. date / venue / race / format の型と値を検証する。
4. resolved_request.json を作成する。
5. Git正本 boat-racing/src/fetch_boatrace_pre_race_info.py をCLIで実行する。
6. 実行結果を独立検証する。
7. validation_report.json を作成する。
8. run_status.txt を作成する。
9. 成果物をartifact化する。
10. BOATRACE_PRE_RACE_RESULT + JSON をIssueコメントへ返す。
11. IssueをCloseする。
12. 取得または検証失敗時もartifactとコメントを残した後でWorkflowを失敗扱いにする。

artifact
--------
基本名:

boatrace-pre-race-<request_id>-<run_id>

主な内容:

- pre_race_result.json または pre_race_result.csv
- resolved_request.json
- validation_report.json
- run_status.txt

Chat側はIssueコメントから run_id / artifact_name / status を取得し、artifactを回収する。

取得する情報
------------
レース全体:
- 日付、会場、会場コード、R
- レース名、レース種別、締切予定時刻、開催何日目、最終日フラグ、距離
- 取得日時、取得状態

艇別の出走表情報:
- 枠番／艇番、選手名、登録番号、級別
- 全国・当地の勝率、2連率、3連率
- 平均ST、モーター・ボートの2連率・3連率
- F数、L数、年齢、体重、支部、出身地
- 今節成績
- コース別成績（公式ページに存在しない場合はNOT_AVAILABLE）
- official_row_text

直前情報:
- 展示タイム6艇
- 展示進入／スタート展示6艇
- exhibition_course
- boat_number
- start_exhibition_st
- 天候、気温、水温、風向、風速、波高

成功判定
----------
fetch_status == success とする必須条件:

- 出走表が6艇
- 展示タイムが6艇
- 展示進入・スタート展示が6艇
- 必須の気象・水面情報が揃う

任意の出走表項目やコース別成績が欠落していても、必須条件を満たせば全体成功とする。

状態値:
- PRESENT: 公式ページから値を取得できた
- BLANK_ON_PAGE: 公式ページ上で空欄または「－」
- MISSING_IN_PAGE: 対象項目・列を検出できない
- NOT_AVAILABLE: 公式ページに情報が掲載されていない

ページ上の空欄と取得失敗を混同しない。
通信・HTML解析等の失敗は failure_kind / failure_message を確認する。

実行後の検証
--------------
Chat側でもartifact回収後に次を確認する。

1. JSONがUTF-8で有効である。
2. fetch_status == success である。
3. racecard_racers が6艇ある。
4. 展示タイムが6艇ある。
5. weather.start_exhibition が6艇ある。
6. 全start_exhibition要素に exhibition_course / boat_number / start_exhibition_st がある。
7. 気温、水温、天候、風向、風速、波高が揃う。
8. 対象日・RがRequestと一致する。
9. source URLがBOAT RACE公式 racelist / beforeinfo のみである。
10. 結果・払戻・オッズ由来の情報が混入していない。
11. validation_report.json の validation_status を確認する。
12. run_status.txt の request_id / issue_number / run_id / head_sha / exit code を確認する。

ユーザーへの返却
------------------
1. 対象日・会場・Rとfetch_statusを簡潔に報告する。
2. 6艇の出走表、展示タイム、展示進入/ST、気象が揃ったかを報告する。
3. artifactから回収・検査した成果物を返却する。
4. 失敗または一部任意項目が未取得の場合は、取得不可項目と理由を短く明記する。
5. 予想を依頼されていない限り、この作業では予想・買い目・評価を出さない。
