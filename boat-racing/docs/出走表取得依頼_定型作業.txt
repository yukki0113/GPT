競艇AI予想：出走表取得依頼の定型作業

対象となる依頼文
------------------
mm/dd について、下記の会場の出走表の取得をお願いします。

会場,会場CD,開催何日目,選別区分
…
…


0. 正本の確認
--------------
1) GitHub yukki0113/GPT の main ブランチを最新化する。
2) 以下を順に確認する。
   - boat-racing/README.md
   - boat-racing/.gpt/CONTEXT.md
   - boat-racing/.gpt/WORKFLOW.md
   - boat-racing/src/fetch_boatrace_racelist.py
   - 必要に応じて同ツールのREADME・テスト
3) 日次CSV、ログ、キャッシュ、台帳はGit管理対象外であり、ソース正本の代わりに参照しない。


1. 依頼内容の受領・入力確認
----------------------------
1) mm/dd を対象年を含む YYYYMMDD へ確定する。
   - 年をまたぐなど年が一意に定まらない場合だけ確認する。
2) 表のうち選別区分が「対象」の会場を取得対象とする。
3) 各対象会場について、会場名・2桁会場CD・開催何日目を確認する。
4) 以下の場合は公式サイトへアクセスする前に停止し、入力不備として伝える。
   - 実在しない日付
   - 会場名と会場CDの不一致
   - 会場CDの重複または不正値
   - 開催何日目の不正値


2. 取得設定の作成
------------------
1) 日付、対象会場（name/code/day）、出力先、リクエスト間隔を設定JSONへ記載する。
2) 会場ごとに1R〜12R、全12レースを対象とする。
3) 公式サイトへの負荷を抑えるため、並列化せず順番に取得する。
4) 取得元はBOAT RACE公式のracelistページだけとする。
   - 展示、直前情報、オッズ、人気、結果、払戻、外部予想は参照・混入させない。


3. 公式出走表の取得・解析
--------------------------
1) 各会場の1R〜12RをPC版公式出走表から取得する。
2) HTTP 200だけでは成功扱いにしない。以下を確認する。
   - HTTPSかつ公式ドメインであること
   - HTML応答かつ本文が空でないこと
   - 出走表テーブルを解析できること
   - ページ内の会場名・会場CD・日付・開催何日目が依頼内容と一致すること
3) PC版が解析不能のときだけスマホ版をフォールバックとして確認する。
   - スマホ版がJavaScript空コンテナ等で選手情報を安全に取れない場合は、推測せず取得不能とする。
4) 一時的な通信失敗および408/425/429/5xxだけを最大2回再試行する。
   - Retry-Afterがあれば尊重する。
   - 404など恒久的なエラーは不要な連続アクセスをしない。
5) 各艇について公式表示のまま、少なくとも以下を構造化する。
   - 日付、会場、場コード、R、締切時刻、開催日目、レース種別
   - 艇番、登録番号、選手名、級別
   - 全国勝率、当地勝率、平均ST、モーター番号、モーター2連率、今節成績、欠場状態
6) 締切時刻は公式の「締切予定時刻」をRごとに取得し、予想入力CSVではRの直後に置く。


4. 正常な空欄と取得失敗の区別
--------------------------------
次は公式ページに値がない正常な表示として、そのまま空欄または「-」で保存する。

- 平均STの「-」
- 今節成績の空欄
- その他、公式出走表に未掲載の成績値

次は取得失敗または一部取得として扱い、成功扱いにしない。

- 日付、会場、R、締切時刻、艇番、登録番号、選手名、級別の欠落
- 艇番1〜6が各1艇ずつ揃わない
- 登録番号・級別・勝率・2連率の形式異常
- 公式ページ識別情報または最終URLの不一致


5. 全体検査
------------
取得後、対象全体について以下を検査する。

- 対象会場数 × 12レース分の取得状況があること
- 日付・会場・R・艇番キーの重複がないこと
- 各レースが1〜6号艇を各1件ずつ持つこと
- 同一レース内で登録番号が重複していないこと
- 予想入力CSVの列順・列数が19列であること
- 取得元URLが公式ドメインであること
- 出力列にAI予想、オッズ、展示、結果、払戻などの禁止情報がないこと

取得不能、一部取得、または全体検査エラーが1件でもあれば終了コード2とし、正常完了として扱わない。


6. 出力と日常の受け渡し
------------------------
実装上は監査用の原本CSV・取得状況CSVも生成するが、日常の受け渡し物は次の2点だけとする。

1) 予想入力CSV
   YYYYMMDD_公式出走表_会場名_会場名….csv
   - UTF-8 BOM
   - 19列
   - 1会場12R × 6艇（通常72行）
   - Rの直後に「締切時刻」列

2) 取得ログ
   YYYYMMDD_出走表取得ログ_会場名_会場名….log
   - HTTP状態、最終URL、再試行、解析状況、検査結果、失敗理由を記録

CSVは同一設定での再実行時に追記せず上書き再生成する。書き込みは一時ファイルを完書きしてから置換し、途中終了による完成CSVの破損を防ぐ。


7. 完了報告の定型
------------------
正常完了時は、次を簡潔に報告する。

- 対象日・会場名
- 対象レース数、出力行数、成功数、再試行数、検査エラーの有無
- 予想入力CSVと取得ログへのリンク

異常時は、次を明示する。

- 対象会場・R
- 取得状態（取得不能/一部取得）
- 公式応答または解析上の具体的な失敗理由
- 予想入力CSVを正常な完成物として使用してはいけないこと


8. ソース改修が必要になった場合
----------------------------------
1) GitHub main を基準に、既存CSV互換性を保って改修する。
2) Python、対応README、必要なテストを同時に更新する。
3) 保存済みfixtureまたは実日付の公式ページで回帰確認する。
4) 日次CSV、ログ、キャッシュ、台帳はcommitしない。
5) 差分とテスト結果を確認したうえで、boat-racing/配下のみをGitHubへ反映する。
