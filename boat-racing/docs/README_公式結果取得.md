# BOAT RACE公式結果取得・予想照合

## 目的と絶対条件

`fetch_boatrace_results.py` は、事前予想CSVの全行を `日付＋会場＋R` でBOAT RACEオフィシャルウェブサイトの結果ページへ結び付け、競走成績・払戻と予想買い目を照合します。

- 参照先はBOAT RACEオフィシャルウェブサイトだけです。
- 結果・着順・払戻の固定値、推測値、仮データ、補完値は使用しません。
- 取得不能・解析不能・入力不正を成功扱いしません。
- 失敗時も監査用CSVを出力しますが、終了コードは非0です。
- 入力CSVにないレースは追加せず、入力1行につき出力1行とします。

## 前提条件とインストール

- Python 3.11以上（3.10でも動作可能な記述ですが、検証対象は3.11以上）
- インターネットから `https://www.boatrace.jp` へHTTPS接続できること

```bash
python -m pip install -r requirements_公式結果取得.txt
```

## 基本実行

```bash
python fetch_boatrace_results.py \
  --input "20260806_事前予想_平和島_三国_宮島_下関_Ver1.1.csv" \
  --output "20260806_結果_平和島_三国_宮島_下関.csv"
```

出力名を省略すると、入力内の日付・会場順から自動生成します。標準実行は、既存キャッシュの有無にかかわらず公式サイトから取得します。

```bash
# 全レースを公式サイトから再取得
python fetch_boatrace_results.py --input INPUT.csv

# 保存済みHTMLを優先し、ないレースだけ公式サイトから取得
python fetch_boatrace_results.py --input INPUT.csv --use-cache
```

キャッシュ限定で再解析：

```bash
python fetch_boatrace_results.py --input INPUT.csv --cache-only
```

主なオプション：

- `--timeout 20`：1回のHTTPタイムアウト秒数
- `--retry 2`：初回以外の再試行回数（既定は合計3回）
- `--interval 1.0`：レース間の待機秒数
- `--cache-dir cache`：キャッシュ保存先
- `--log FILE.log`：ログ出力先
- `--unit-stake 100`：1点あたり予定購入額。100円単位
- `--strict`：中止・不成立も含め、全行が「取得成功」でなければ非0終了
- `--limit N`：開発時の先頭N件確認専用。これを付けた実行は必ず異常終了扱い

## 入力CSV仕様

UTF-8（BOM有無どちらも可）を読み込みます。必須列は次のとおりです。

`日付, 会場, R, 判定, 主推奨券種, 主推奨買い目展開後, 主推奨点数, 保険券種, 保険買い目, 保険点数, 参考券種, 参考買い目, 予想確定日時`

列名は変更しません。日付は `YYYY-MM-DD`、`YYYY/MM/DD`、`YYYYMMDD`、Rは `1` または `1R` に対応します。`日付＋会場＋R` の重複は入力不正です。

## 公式ページの検証と取得項目

URLは `https://www.boatrace.jp/owpc/pc/race/raceresult?rno=R&jcd=CD&hd=YYYYMMDD` です。HTTP 200だけでは成功にせず、HTML内の会場画像alt、開催日タブ、選択中Rのリンクパラメータも入力キーと照合します。

取得する構造化情報は、確定着順、着順詳細、3連単・3連複・2連単・2連複・拡連複・単勝・複勝、返還艇、欠場艇、失格艇、事故艇、備考、中止、不成立です。`妨` は失格艇、`転・落・沈・不完走` は事故艇として艇番を残し、公式の着表示そのものは着順詳細にも保存します。監査情報として公式URL、HTTPステータス、HTTP取得日時、結果確認日時、HTMLのSHA-256を保存します。

## 買い目展開ルール

- 区切り：`／`、`/`、改行、セミコロン
- 順序：`→`、`⇒`、`->`、`-`
- 組合せ：`=`
- 複数候補：半角・全角カンマ
- 逆転：`1⇔2→3,4`

例：`1→2,3→2,3,4` は同一艇重複を除き、`1-2-3, 1-2-4, 1-3-2, 1-3-4` へ展開します。3連複・2連複・拡連複は艇番を昇順に正規化し、3連単・2連単は順序を保持します。展開後は重複を一意化します。

主推奨・保険は、展開件数とCSVの点数が一致しなければ入力不正です。参考は点数列がないため、実際の展開件数を採用します。

## 的中・返還・投資額

1点あたり既定100円で、各区分に次を出力します。

- 購入予定額 = 展開後点数 × 1点額
- 返還額 = 返還対象点数 × 1点額
- 返還後投資額 = 購入予定額 − 返還額
- 的中払戻 = 公式払戻（100円当たり）× 1点額 ÷ 100

返還艇を含む買い目だけを返還対象とし、的中照合から除外します。中止・不成立は区分内の全買い目を返還対象とします。返還額は的中払戻に加算しません。

## 中止・不成立・未確定

- 公式備考等に中止が明示された場合：`開催中止`
- 不成立が明示された場合：`レース不成立`
- ページ同一性は確認できたが、確定着順・払戻が未掲載：`公式未確定`
- 確定した通常レースで必須7券種または上位3着を解析不能：`解析失敗`

中止・不成立は通常モードでは明確な終端状態として扱います。`--strict` では非0終了です。公式未確定は常に非0終了です。

## 出力CSV

入力のキー・判定、公式結果、全券種払戻、主推奨・保険・参考の購入予定額／返還額／返還後投資額／的中／的中買い目／的中払戻、返還・欠場・失格、中止・不成立、監査列をUTF-8 BOM付きCSVで出力します。

監査必須列は `取得状態, 公式URL, HTTP取得日時, 結果確認日時, エラー内容` です。追加で `HTTPステータス, HTML_SHA256` を保持します。

## キャッシュ仕様

```text
cache/YYYYMMDD/会場CD/RR.html
cache/YYYYMMDD/会場CD/RR.meta.json
```

メタデータには元URL、HTTP取得日時、HTTPステータス、SHA-256、バイト数を保存します。通常実行は必ずネットワーク取得です。`--use-cache` はキャッシュ優先、`--cache-only` はキャッシュ限定、`--refresh` は既存キャッシュを無視してネットワーク再取得です。キャッシュ利用時はURLとSHA-256を再検証し、不一致なら解析失敗です。

キャッシュ利用時は、URL・SHA-256に加えて、保存バイト数、HTTP 200、タイムゾーン付き取得日時も検証します。HTMLとメタデータ、結果CSVは一時ファイルへの書込み後に置換するため、処理中断で途中書込みのファイルを正常成果物として残しません。HTMLとメタデータの置換間で中断した場合も、次回のSHA-256またはバイト数検査で不整合を検知します。

## ログ仕様

ログには実行開始・終了、取得モードと主要オプション、入力／処理行数、全対象キーと公式URL、HTTP状態、取得日時、ネットワーク／キャッシュの別、解析状態、エラー、状態別件数、取得元別件数、出力件数、URL件数、重複・未結合・余剰件数、仮データ生成機能・結果固定値使用機能が未実装であること、正常／異常終了を記録します。HTML全文はログへ出しません。ログ接頭辞と本文中の日時はいずれもJSTです。同じログ名で再実行した場合は、前回ログへ追記せず、その1実行分で置き換えます。

## 正常終了条件

通常モードの終了コード0は、全件処理、入力＝出力件数、キー重複・未結合・余剰なし、URL全件記録、取得失敗・解析失敗・入力不正・公式未確定なしを満たす場合だけです。`--limit` は全件成果物ではないため必ず非0です。

終了コード：

- `0`：正常終了
- `1`：監査条件未達（CSV・ログは確認可能）
- `2`：入力ファイル全体またはコマンド引数の不正

異常終了時はログ末尾の `未完了対象` と、CSVの `取得状態`・`エラー内容` を確認してください。

## 既知の制約とHTML変更時の対応

- BOAT RACE公式HTMLの見出しやCSSクラスが変わると解析失敗になります。
- 異常応答によるメモリ負荷を避けるため、1ページのHTML取得上限は5 MiBです。通常の公式結果ページはこの範囲内です。
- 同着などで同券種に複数の公式払戻が掲載される場合は複数行を保持して照合します。
- 着順表の艇番・数値着順、または同一券種の公式組番に重複を検出した場合は、曖昧なまま成功扱いせず解析失敗とします。
- 欠場・失格の表示方法が公式HTMLで変わった場合は、保存済みキャッシュを証跡としてパーサーを修正し、`--cache-only` で再解析します。
- 公式ページに返還艇が表示されない限り、返還を推測しません。
- 公式情報を取得できない場合、値を補完せず、成功扱いにしません。

## 回帰テスト

主要な異常系は標準ライブラリの `unittest` で確認できます。

```bash
python -m unittest -v test_fetch_boatrace_results.py
```

実運用キャッシュの全件再解析は、対象の予想CSVごとに `--cache-only` を指定して行います。キャッシュ読込だけの行には `--interval` の待機を入れないため、ネットワークへアクセスせず短時間で再解析できます。
