# 競馬予想 実行手順（必須順序・完了判定）

> 最上位の判断基準は [FORECAST_POLICY.md](./FORECAST_POLICY.md)。本書はその実行手順と検証ゲートであり、予想方針の上書きではない。人力予想実例は [TEACHER_EVIDENCE.md](./TEACHER_EVIDENCE.md) を参照。

## 禁止事項

- **IDM・調教指数・基準人気が高い馬を先に◎に決め、過去統計を後付けで根拠づけしない。**
- **脚質コードだけで実際の走りを決めつけない。** 前走の通過順位、位置取り、相手の脚質、ペース想定を別々に確認する。
- 不都合な統計や条件不一致を、説明なしで省略しない。
- 抽出サンプル数が少ない場合に、無関係な条件で水増ししない。
- 欠損・未取得・照合失敗を推測値で埋めない。集計が成功していないのに「確認済み」と表記しない。
- **集計処理の成功を予想評価の完了と混同しない。**

## 0. 最初に必ず読むファイル

1. [FORECAST_POLICY.md](./FORECAST_POLICY.md) — 判断方針の正本。
2. 本書 — 順序・検証項目・停止条件。
3. [TEACHER_EVIDENCE.md](./TEACHER_EVIDENCE.md) — 人力予想実例への参照。印そのものを正解ラベルとして学習しない。

## バックテストの時点固定・外部検索禁止

- **過去・終了済みのレースであっても必ず予想する。** 終了済みという理由で予想を取りやめたり、「結果が出ているから事前予想ではない」と判定しない。
- 予想フェーズでは、指定されたJRDBの事前用資産（PACIなど）と、対象レースより前の情報のみを参照する。過去レースの歴史的な着順は統計母集団として利用可。ただし対象レース・その後の結果は参照不可。
- **対象レースの結果、払戻、確定着順をWeb検索しない。** JRDBの保存済みデータで事前予想を再現することが目的。予想フェーズでは他のWeb記事、検索スニペット等から結果を補完・照会することもしない。
- `as_of`（予想時点）とデータの版・ハッシュを記録し、結果や事後更新を含む未来情報が混入していないことを確認する。
- 予想完了時に印、根拠、買い目、入力データ版を**先に確定・保存**する。その後の別フェーズで初めて結果データにアクセスして評価する。
- もし対象レースの結果を予想確定前に知ってしまった場合、その事実を記録し、**新たな予想を未汚染バックテストとして扱わない**。結果への適合を意図して印を変更しない。

## 1. 対象レース・データの固定

- レース日・競馬場・R・レース名・芝/ダート・距離・クラス・性齢・施行時期を記録。
- 予想対象年の前年までの **10暦年**を固定（2026年なら2016〜2025年）。
- 当日PACIおよび最新の検証済みAnalysis Parquetを取得し、file ID、SHA-256、サイズ、対象日・版を監査。
- 再利用する統計データは同一版で統一し、予想対象当日の結果データが混入しないようにする。
- Parquet/DuckDBは共通 `tools/data-storage/` を使用。ローカル不可なら既存のGitHub Actions fallbackを使用し、完了・audit PASS・JSON成果物取得まで確認する。

## 2. 過去レースを抽出して集計母集団を確定

- レース名付き特別競走は**同名かつ同条件**を最優先して抽出。
- **レース単位のサンプル数**（開催回数）と**出走馬延べ頭数**を明確に区別する。
- 同名・同条件の該当数が **4レース以下**なら、不足を明示したうえで条件が極力近い別レースを追加。元の完全一致サンプルと補完サンプルを混合表示しない。
- 類似条件の採否は、コース・距離・芝ダ・クラス・施行時期・性齢限定等の一致/不一致を記録する。
- 過去10年の対象範囲と重複、欠損、開催条件の変更を監査する。

**ゲートA**：期間・同名同条件・レース数・延べ出走頭数・補完理由が確認できなければ次に進まない。

## 3. 過去傾向を先に構築する（印はまだ付けない）

必須の8軸を**すべて**検討する。

| 軸 | 確認事項 |
|---|---|
| 人気 | 人気帯ごとの好走実績 |
| 枠順 | 枠別の好走実績 |
| 脚質 | 逃げ/先行/差し/追込等の好走実績。分類定義・実際の通過順との違いに注意 |
| 馬齢 | 年齢別実績。年齢限定戦では有効な比較にならないことも明記 |
| 血統 | 種牡馬等の利用可能な血統粒度とサンプル数 |
| 騎手 | 騎手別の実績とサンプル数 |
| 前走距離 | 今走との距離増減、前走距離帯 |
| 前走クラス | 前走レース格・クラス別実績 |

- 各集計に母数・着別度数 `(1着-2着-3着-着外)` と条件解釈を付記する。
- 軸が分析不能なら「未取得/欠損/比較不能」の理由を残し、分析済みと装わない。
- 傾向は単純な勝率の高低のみでなく、絶対件数・母数・再現性も含めて解釈する。
- **同名・同条件への特化と少数実例を積極的に評価する。** 『過去8回しかない』という理由だけで、特定レースに強い騎手・血統・脚質などの一致を割り引かない。例えば菊花賞（京都開催）での騎手別 (5-1-0-2) は、このレースへの強い適合シグナルとして扱う。単独で◎確定とはせず、他軸・個別事情も突き合わせる。母数・適用範囲は併記するが、一般論の小標本警告で予想の主軸を弱めない。
- 同名同条件が4レース以下の場合のみ、方針の基準に従って補完する。単純に母数を増やす目的で異なる条件を混ぜない。

**ゲートB**：8軸の集計結果か欠損理由がそろい、レース全体の好走/不振条件が先に整理されるまで**◎○▲△を決めない**。

## 4. PACIと過去傾向を出走全馬について照合する

- **全出走馬**について馬番・馬名・枠・性齢・騎手・血統・前走距離/クラス・前走の内容を確認する。
- 各馬がどの好走条件に**一致/不一致/不明**なのか、横並びの比較表を作る。
- 前走1走の走行実態（通過順位、位置取り、先頭通過、差し/追込など）を読んで、静的な脚質コードとのずれを明記する。
- 「逃げが過去0勝」のような統計があるなら、過去に逃げた経験がある馬を本命にする際には、**今回逃げる想定か、先行に控えられると見る根拠か、その不利を上回る別の条件一致があるか**を比較して説明する。
- 逃げ経験だけを理由に自動消しもしない（方針の「機械的除外禁止」を維持）。

**ゲートC**：出走全馬の同一基準による横並び比較と、重要な負傾向との矛盾点の検証が済むまで◎を付けない。

## 5. 補足材料による最終調整

- 前走の相手関係、着順の内容、不利、レースレベル、適性、実力指数、調教を**ここで**検討する。
- 調整前（統計ベース）の評価と調整後の評価を分け、変更理由を具体的に記録する。
- 指数上位だからという理由のみで統計評価を覆さない。逆転させるなら、統計側で不利な点も示して合理的に説明する。

**ゲートD**：調整前後の順位、逆転理由、各候補の懸念点を記録する。

## 6. 印・買い目を決定する

- ◎は単純な最大指数馬や最も勝率が高そうな馬ではなく、**最も買いたい馬**。
- ◎○▲△☆の理由は「過去傾向の一致→個別の補足」の順で記述する。
- 最有力が定まらないときは「明確な軸不在」と明示。無理に強い軸を装わない。
- 買い目を示すなら、採用理由、点数、金額の前提を印と整合させる。オッズ未確認の配分は断定しない。

## 7. 発表前の最終照合（全チェックが必要）

- [ ] 前年までの10暦年を使用した。
- [ ] 同名同条件のレース数・母数を確認し、4以下の場合の補完を分離した。
- [ ] 8軸すべてについて結果または欠損理由を示した。
- [ ] PACIの全出走馬を確認して横比較した。
- [ ] 脚質コードと前走通過順位を混同していない。
- [ ] 本命馬の不利な傾向・条件不一致も説明できる。
- [ ] 過去傾向評価を指数・調教より先に確定した。
- [ ] 事前データのみを使い、結果の未来情報を混入していない。
- [ ] Actions/実行監査がPASSで、使用した成果物を確認した。
- [ ] 印と買い目の理由を過去傾向から説明できる。

**いずれか未達なら「方針準拠の最終予想」として公表しない。** 取得できた範囲の暫定分析と不足点を区別して提示する。

## 反省事例：2026-10-24 アルテミスS

過去の「逃げ0勝」という集計を掲げながら、新馬戦で `1-1-1-1`、前走で `3-3` の⑤を、PACIの高いIDMと「先行型」という脚質コードを主因に◎とした。これは**ゲートB→C→Dの順序違反**。全馬比較をせず指数上位を先に選び、脚質コードで実際の走りを上書きし、負傾向を検証しなかった。再発防止は機械的な「逃げ馬除外」ではなく、矛盾の検証・記録を印確定の前提とすること。
