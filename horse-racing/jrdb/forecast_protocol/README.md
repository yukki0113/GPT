# 競馬予想プロトコル（読み込み入口）

**このディレクトリは人手統計重視の競馬予想における唯一の手順入口です。** RaceNote等の既存モデル予想ロジックを自動変更するものではありません。GPTが人手統計重視の予想を依頼された場合は、印を考える前に以下を順に読みます。

1. [FORECAST_POLICY.md](./FORECAST_POLICY.md) — **ユーザーが確定した原文の予想方針**。期間・条件・8集計軸・優先順位の正本。
2. [FORECAST_PROCEDURE.md](./FORECAST_PROCEDURE.md) — 実行順序、ゲートA〜D、公開前チェック。
3. [TEACHER_EVIDENCE.md](./TEACHER_EVIDENCE.md) — 人力予想の正本ファイルへの参照。

## 適用範囲と優先順位

- 対象：ユーザーが明示的に依頼する、JRDB/PACI・過去レース統計を用いた人手型のレース予想。
- 予想方針は本ディレクトリの`FORECAST_POLICY.md`を正本とする。手順書は**解釈・検証の補助**であり方針を書き換えない。
- 2026年の統計対象は**2016〜2025年**。予想対象年を含めない。
- 対象のレースが名称を持つ特別競走なら同名同条件優先、4レース以下なら類似条件を分離して補完する。
- 先に**過去好走条件**を出し、その後でPACI全頭を比較し、最後に指数などで調整する。順番を逆転させない。
- データ基盤は共通の`tools/data-storage/`と動的Driveマニフェスト・Actions fallbackを利用。これは輸送・計算手段であり予想方針に代わるものではない。
- ゲート未達の場合は最終印・買い目を「方針準拠済み」と称さず、未完として報告する。

## 新しい会話・作業者への指示

予想に着手する前に`horse-racing/jrdb/forecast_protocol/README.md`から3文書を開く。印の作成前には手順書のゲートA、B、Cの充足を確認し、最終回答前にDとチェックリストを照合する。

**禁止する典型例：** まず高IDMの馬を◎に決め、後から過去傾向と一致する部分だけ引用する。静的脚質コードだけを見て前走`1-1-1-1`のような走行実態を無視する。
