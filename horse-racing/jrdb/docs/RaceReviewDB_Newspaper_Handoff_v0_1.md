# RaceReviewDB -> Newspaper/PWA Recommendation Handoff v0.1

Status: ACTIVE
Date: 2026-10-01

## 1. Purpose

RaceReviewDB internal recommendation evidence and Newspaper/PWA reader-facing
presentation are separate contracts.

RaceNote / forecast internal use may consume:

- signal IDs
- measured strength values
- raw RRDB fields
- recommendation provenance

Newspaper/PWA must not depend on those internal details.

For Newspaper/PWA, RRDB exports only:

- exact target-horse identity
- one reader-facing short comment
- recommendation contract version

The short comment is generated by RRDB. Newspaper does not reinterpret or
recompute RRDB signals.

## 2. Source of truth

Current recommendation contract:

`docs/RaceReviewDB_Recommendation_Operation_v0_2.md`

Signal implementation and reader-facing translation:

`src/jrdb_recommendation_signals.py`

Sparse handoff builder:

`src/build_rrdb_newspaper_handoff.py`

## 3. Handoff unit

One CSV per target date.

Recommended filename:

`RRDB_recommendation_YYYYMMDD_PWA_handoff_v0_1.csv`

This is a sparse source: only matched recommendation horses are present.

Required columns:

```text
date
venue_code
race_no
race_key
horse_no
horse_name
recommendation_comment
recommendation_version
```

## 4. Comment semantics

The PWA comment must be racing prose, not an internal code dump.

Canonical reader-facing phrases:

- `TIME_CLASS_PLUS1` -> `前走時計はクラス水準より上。`
- `FRONT_SURVIVE_GAP05` -> `前傾ラップ戦を前で受け、勝ち馬と僅差まで踏ん張った。`
- `REAR_HIGH_LAST3F90` -> `後傾ラップ戦も後方から上位の上がりは使った。`
- `HV01 / HV02` -> `敗戦でもタイムは水準以上。`

When independent concepts coexist, RRDB may join them into one compact comment.
Do not repeat two near-synonymous time comments when TIME_CLASS and HV overlap.

## 5. Hidden internal information

Do not export these as the Newspaper/PWA display contract:

- `signal_id`
- `matched_signal_count`
- S/A or any recommendation grade
- raw strength JSON
- internal threshold constants

They remain available inside RRDB/RaceNote where needed.

## 6. Merge policy

Newspaper consumes the CSV through:

`src/jrdb_newspaper_merge_external.py --rrdb-recommendation-csv ...`

Join key:

`date + venue_code + race_no + horse_no`

Cross-check:

- `race_key`
- `horse_name`

No fuzzy horse-name join or inferred race identity.

Because the source is sparse:

- non-listed horses are normal and receive no RRDB addon;
- every listed row must be consumed exactly once;
- duplicate / extra / identity mismatch fails closed.

Projection:

```json
{
  "addons": {
    "rrdb_recommendation": {
      "comment": "<reader-facing short comment>",
      "source": "RaceReviewDB",
      "source_date": "YYYY-MM-DD",
      "version": "rrdb-recommendation-signals-v0.2"
    }
  }
}
```

## 7. PWA presentation

RRDB does not own a standalone Newspaper column.

Use the existing RaceNote mark cell:

- if an RRDB target already has a RaceNote mark, keep that mark and make the mark tappable;
- if an RRDB target has no RaceNote mark, display `注` and make it tappable;
- the modal shows the supplied RRDB short comment;
- when a RaceNote horse comment also exists, preserve it and show both comments in the same modal;
- non-RRDB horses are unchanged;
- PWA does not show internal signal IDs or strength structures.

RRDB must not replace an existing RaceNote mark with `注`.

## 8. Ownership boundary

RRDB owns:

- recommendation conditions
- signal strength
- short-comment translation

Newspaper owns:

- exact merge
- source-status/audit
- rendering the supplied comment

Newspaper must not:

- re-evaluate whether a horse qualifies;
- rank RRDB recommendations;
- create S/A grades;
- rewrite the supplied comment from raw values.

## 9. Relationship to RaceNote

This handoff is independent from `addons.racenote_prediction`.

A horse may have:

- RaceNote prediction mark/comment
- RRDB recommendation comment
- both
- neither

They remain separate data namespaces internally. Presentation may share the existing
RaceNote mark cell according to section 7; this is only a UI projection and does
not merge the underlying evidence contracts.
