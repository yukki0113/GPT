# RaceNote v0.5.6 — B/C軸信頼度 Shadow研究運用（2026-11-04）

Status: **RESEARCH ONLY / PROPOSED**。本書はv0.5.6の稼働中A/B/C/Z判断・本番馬券規則を変更しない。新規BTDAYの起動・既存Freezeの変更・過去900Rの再格付けを許可しない。

## 1. 位置づけ／研究目的

従来Confidence（正本）は「**◎が1着になる確信度**」であり、v056の既存 `confidence_review`（`winning_case`, `primary_rival`, `relative_advantage`, `main_defeat_scenario`, `risk_assessment`, `final_grade_reason`）をそのまま使用する。

- **A（正本・保護対象）**：◎を勝ち馬として明確に最有力と認める。A/B境界を変更しない。積極購入を検討できる現在の選別品質を維持。
- **B（正本）**：◎を勝ち馬として優先するが、相手の逆転・条件的不確実性が残る。
- **C（正本）**：◎の勝ち筋は不安定／不確実性が大きい。
- **Z（正本）**：元の適用除外定義のまま。

これとは別に、**Shadow B/C**は「凍結済み5頭の中で◎を馬券の軸として固定できる、結果非参照の説明可能な根拠があるか」を評価する。既存Confidenceの優先順位も印も変えない。馬券推奨を自動化しない。

## 2. Shadow B/Cの境界と判断材料

- **Shadow B（軸候補）**：凍結済み◎を5頭内の軸に固定する積極的根拠が示せる。根拠は能力・当該条件適性・レース構造・再現可能な近走内容など、当該Readerで確認できる事前証拠に基づく。○▲らに逆転余地があっても、◎の比較優位または軸としての堅実さを説明できる。
- **Shadow C（軸不確実）**：5頭候補は成立するが、◎だけを固定する根拠が弱い／未実証の重要条件に依存する／○▲等と序列が実質拮抗している。◎が勝つ可能性自体を否定する判定ではない。
- 単なる初距離・強敵の存在・一般的リスク語だけで機械的にCへ落とさない。固定閾値・自動スコア・B/C件数目標は設けない。
- 結果的な勝利・高配当を根拠に再格付けしない。結果を先に知っている歴史的900Rは新基準の独立検証標本として使わない。

### 人間／LLMが各レースで確認する問い

1. **軸の正の根拠**：◎を他の印馬より先に選び、連対・3着内を含む軸に固定できる具体的事前証拠は何か。
2. **直接比較**：○を中心とする最有力の逆転候補と比較して、◎の優位はどこにあり、どこが弱いか。
3. **前提依存**：その根拠は、未経験のコース・距離・馬場・展開等の重大な仮説成立に過度に依存するか。
4. **敗北シナリオ**：◎が軸から外れる合理的なシナリオと、その蓋然性の判断材料は何か。
5. **結論**：Shadow B/Cを明記し、正本と不一致なら理由を説明する。

判定は**事前情報を読むLLMが各R独立で著述**する。Pythonは整合性・保存形式の検査のみを行う。

## 3. 保存位置と既存Freezeの保護

現行v056 Prediction Freeze `frozen/records.json` → Confidence Freeze `confidence_frozen/records.json` が**main上で双方完了・検証済み**であることを前提とする。Shadowはこの2段階Freezeの**後**、結果／当日市場／払戻を開く**前**に作成する。既存コホートの解除条件をShadowで置き換えない。通常運用の`TURN2_COMPLETE`条件にShadowを追加しない。

研究データは既存 `frozen/`, `confidence_frozen/`, `incoming/`, `session.json` を一切上書きしない別成果物として管理する。推奨場所は研究専用 `horse-racing/jrdb/research/bc_shadow/<selection_id>/<session_id>/`。本ツールは既存v056 rootに**読み取り専用**でアクセスし、`--output`に指定された別パスへ新規ファイルを排他的に保存する。

提出用JSONは次の形（B/Cだけを対象とし、A/Zは記録の対象外）：

```json
[
  {
    "venue": "東京",
    "race_no": 1,
    "honmei": 3,
    "shadow_grade": "B",
    "axis_positive_case": "今回の条件で再現可能な◎の先行実績があり、○より位置取りの優位を見込める。",
    "strongest_rival": 7,
    "relative_axis_case": "○7にも差し脚はあるが、想定隊列では◎の安定した位置取りを優先できる。",
    "unverified_assumptions": "流れが極端に速くならないという前提は残る。",
    "axis_failure_scenario": "先行争いが激化すると◎の連対・3着内が損なわれる。",
    "final_reason": "大きな不確実性はあるものの軸固定の正の根拠が存在するためB。"
  }
]
```

※上記は**形式例**であり、実在レース・実在馬の判定でも検証入力でもない。文字列をテンプレとして使い回さない。

### 原票との結合・不変条件

- v056 `session_id`、`selection_id`、`target_date`、Prediction records SHA、Confidence records SHAを保存し、参照元を一意に識別。
- 提出対象は**正本ConfidenceでB/CのRすべて・ちょうど1レコードずつ**。A/ZはShadow対象外として現行のまま固定。
- `(venue, race_no, honmei)` は凍結済みPrediction／Confidenceと完全一致。競争相手は凍結済み印内の◎以外を実在馬番で指定する。
- 正本B/CとShadow B/Cは別列に保持し、元の自信度は変更しない。
- 提出前に結果が解禁されていないことを運用者が明示確認する。既存handoffの`result_opened=false`は凍結時点の証拠であり、後日の未閲覧を証明しない。すでに結果を参照したレースではShadowを新規著述せず研究対象から除外する。
- SHA参照・全Rカバレッジ・重複・A/Zへの混入・空理由・禁止語・旧v055参照をFail Closedで検査。**判定文の妥当性そのものはLLMでレビュー**し、validator PASSだけで品質合格としない。
- Shadow原票も**結果解禁前の独立したcommit/Artifact**として固定し、結果後の上書きを禁止。ローカルJSON出力の生成だけではGit正本のFreeze完了とは宣言しない。

## 4. 実行と検証の段階

1. v056新規BTDAYの二段階Freezeがmainに永続化されたことを確認。適用前に最新運用手順・session/Readerを確認。
2. 結果非参照のまま全B/Cレースについて上記5問をLLMが独立著述し、`shadow_draft.json`を作る。A/Zを著述しない。
3. `python horse-racing/jrdb/src/racenote_v056_bc_shadow.py --root <v056-root> --draft <shadow_draft.json> --output <research-only-new-file.json> --assert-results-unopened`。このフラグは運用者による**その時点の未閲覧宣言**であり、ツールだけで未来の結果非閲覧を保証するものではない。
4. 出力のSHA・出典SHA・正本/Shadowの件数・不一致数を確認。独立研究成果物を結果解禁前に永続保存し、上書きしない。確認できない場合は結果分析に利用しない。
5. 既存の結果解禁ゲートに従い正規JRDB Result Queryにより照合。**Aの品質、B/Cの◎勝率・3着内率、◎軸馬連4点、◎軸3連複6点、3連複5頭BOX10点の的中率・全払戻回収率**を監査する。各点100円。見送り（投資0円）を独立選択肢とする。
6. まず3BTDAY程度で運用適合を確認し、次いで累計10BTDAY程度を中間点にする。Cの件数不足なら延長。3／10日はいずれも**統計的達成基準ではない**。閾値の過去最適化を禁止し、別期間／forwardで再現確認する。

## 5. 運用上の禁止事項

- A/B境界・正本Aの判断・印・既存Freezeの変更。
- Shadowを根拠とした予想時点での印の付け直し、過去データの結果参照後のShadow付与。
- 正本v056 `confidence_review`の意味（◎勝利確信）をShadowの意味（軸固定の根拠）で上書き。
- 高配当の上位1/2/3件を恣意的に除いた回収率を**正式評価**として採用。全払戻を正として評価し、別途必要なら分散・最大連敗・資金変動を補助資料とする。

## 6. 現状と適用境界

このPRでは運用研究定義と別系統Shadow原票の入力検証・保存手段のみを用意する。既存T2 Workflowに自動挿入しない。新規BTDAYを実行しない。v056が実運用で対象レースについて検証・永続Freezeまで完了しているかは、各BTDAYごとに確認する。
