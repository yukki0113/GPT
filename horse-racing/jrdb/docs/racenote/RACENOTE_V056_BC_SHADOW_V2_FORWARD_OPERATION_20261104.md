# RaceNote v0.5.6 — Shadow B/C運用定義 v2（前方検証専用）

- **Status:** RESEARCH / FORWARD ONLY / FROZEN SPECIFICATION
- **制定:** 2026-11-04
- **適用:** 本書をGitに固定した後、結果に触れずに新たに判定するBTDAYのみ
- **非適用:** BTDAY-0152〜0161（v1の309R・Shadow 224R）は**判定を再作成・上書きしない**
- **対象:** 既存ConfidenceでB/Cのレースのみ。正本A/ZはShadow判定対象外。
- **禁止:** v0.5.6の印／正本Confidence／Prediction Freeze／Confidence Freeze／T2／本番購入規則の変更

## 1. 改訂の目的と根拠の位置づけ

v1の10 BTDAY・309Rの**検証結果を見た後の仮説改訂**である。新しい独立標本による性能実証ではない。

v1の検証では：
- 既存C→Shadow B：13R中◎3着以内9R（69.2%）、既存C→Shadow C：24R中7R（29.2%）。
- 既存B→Shadow B：138R中◎3着以内79R（57.2%）、既存B→Shadow C：49R中28R（57.1%）。
- **失敗箇所**：B→Cで◎の3着内率を区別できなかった。◎と○の勝利可能性が拮抗しているだけで、◎の馬券内安定性を過小評価する危険を認める。
- 高配当や的中を評価から恣意的に外さない。上記は**v2設計動機**であって新基準の的中根拠ではない。

**核心**：「○が◎を負かす」≠「◎が3着以内から消える」。◎単独の馬券内信頼性と、相手が逆転する可能性を別に考える。

## 2. 正本とShadowの責務を混ぜない

| 系統 | 評価対象 | v2の影響 |
|---|---|---|
| Prediction Freeze | ◎○▲△△の5頭と順序 | なし |
| Confidence Freeze | ◎の**1着確信度**（A/B/C/Z） | なし |
| Shadow B/C v2 | ◎を固定軸とする**着内再現性・軸としてのリスク** | 独立した研究ラベルのみ |
| 馬券評価 | ◎軸／BOX／見送りなどの損益 | **事後評価専用**。Shadow付与時に払戻・結果を参照しない |

Shadow B/Cは必ず**元のA/Zを触らず、元B/Cだけを二値評価**する。「Bのほうが配当が低い／Cのほうが妙味がある」といったオッズや期待回収率では決めない。

## 3. v2の境界（必須条件）

### Shadow B：◎を着内軸に固定する積極根拠がある

次の双方を満たすこと：

1. **着内再現性の正の証拠**を事前情報から具体的に挙げられる。例：類似距離／コース／クラスでの複数回の上位着順、持続できる先行位置、末脚の再現、実走指数と馬場・隊列への耐性など。単発好走も条件の適合と裏付けが十分なら認めるが、数値・調教評価だけを理由としない。
2. **◎が馬券外になる主要な経路を検討**してなお、固定軸として選ぶ判断を合理的に説明できる。○の勝利や他馬の好走を認めても、◎自身が3着内に残る見通しがあるならBを維持する。

元ConfidenceがCでも上記を満たせばC→Shadow Bは許容する。勝ち切りに不安があることだけをC維持の理由にしない。

### Shadow C：◎が馬券外になる具体的な失敗経路が重要で、軸として固定しにくい

次の双方を満たすこと：

1. **具体的な着外シナリオ**を、◎の弱点と当該条件に紐付けて明示する。例：同型馬との競り合いによる消耗、距離延長で末脚・先行持続の失速、馬場・ペース変化への実証不足、近走で反復する着外、展開依存で位置を失うなど。必ず**◎が4着以下になる経路**として記述する。
2. そのシナリオが**今回のレースで無視できないことを示す事前証拠**を提示し、Bにする積極的根拠との比較で「◎を軸に固定しない」が合理的な理由を説明する。

元ConfidenceがBなら**B→Cは特に反証を要求する**。元BをそのままCに落とす理由として「○と能力値が近い」「○が勝てる」「◎の勝率が低い」「◎が1着を逃す」「僅差」「混戦」だけを使うことは禁止する。これらは必要なら追加の質問を開始する材料に過ぎない。

### 判定不能／材料不足

- **根拠不足は自動的なC判定ではない**。Bに必要な正の証拠もCに必要な着外シナリオも足りない場合、結果を見ずにReader等の追加事前材料を確認する。
- 追加情報でも解消しなければ、**`review_required`として研究監査に隔離**し、LLMがB/Cを捏造しない。v1のvalidatorはB/C二値・全件必須のため、`review_required`のまま通過させず研究Freezeを停止する。正本T2の完了は維持する。
- 「Bが多すぎる／Cが少なすぎる」という件数目標、全件Bへの機械的フォールバック、能力値差の固定閾値による自動格付けを禁止する。

## 4. 事前に読むべき材料と著述手順

**原則**：当該BTDAYの凍結済みPrediction／Confidenceに加え、必要に応じて結果が未参照の当該Reader事前情報を読む。過去走・指数の既往は利用可。対象レースの結果・払戻・確定人気・事後コメントは不可。

レースごとに、以下の独立した問いに答える：

1. **◎の着内正の根拠（必須）**：同条件・類似条件で着内に残れる事前証拠。事実・日時・クラス・距離・指数・馬番など検証可能な記述で示す。
2. **○および残りの印との比較（必須）**：○だけでなく▲△△も見て、◎の着内軸信頼性を相対的に考える。ただし、相手の**1着逆転**を◎の**着外**と混同しない。
3. **◎の着外経路（必須）**：◎が4着以下となる具体的展開と、実際にその経路の可能性を高める事前証拠を記述。一般的な「展開次第」だけでは不足。
4. **正の根拠と着外リスクの比較（必須）**：なぜ着内軸に据える／据えないのかを説明する。単純な能力値差・KYI・調教値の羅列ではなく競馬的な因果を言語化する。
5. **結論（必須）**：Shadow B/Cとその理由。元Confidenceと異なる場合は、**勝ち切り確信度と着内軸判断が異なる理由**を明記する。

### ケース別の特別な問い

- **元B→Shadow Cを提案する場合**：
  「○が勝つとして、なぜ◎は2着・3着に残れないのか？」
  「既存のBの正の根拠を、どの具体的な事前証拠で覆したか？」
  この2問への実証的な回答がない場合は**B→Cを認めない**。単なる能力拮抗の場合は元Bを維持するのが合理的。
- **元C→Shadow Bを提案する場合**：
  「◎が1着を取り切れない要因を認めつつ、なぜ2着・3着内への再現性はあるのか？」
  この2つを切り分けて書けなければBへの引き上げを認めない。
- **元B→B／C→Cの場合**：ラベル維持だけで説明を省略しない。各Rの固有根拠を書く。

### 形式例（架空・実レースではない）

元B・◎4・○9の場合：
- **Shadow B**：「○9の逃げ切りはあり得るが、◎4には同クラスで先行から2〜3着に残した複数回の実績があり、競られても極端に失速していない。○の逆転だけでは◎の着外シナリオを示せない」
- **Shadow C**：「◎4は同距離で同型との競り合いが発生した2戦とも4着以下で、今回も○9・▲7が先手主張型。◎の着外経路が具体的かつ再発し得るため固定軸は避ける」

説明の品質を監査するための架空例であり、実際の判定・数値・統計的な閾値には使わない。

## 5. 既存実装との互換性・監査

v2は**研究判定方法の改訂のみ**。現状の`racenote_v056_bc_shadow.py`の入力キー：
`venue, race_no, honmei, shadow_grade, strongest_rival, axis_positive_case, relative_axis_case, unverified_assumptions, axis_failure_scenario, final_reason`を維持し、既存の結果非参照Freeze検証器を変更しない。

各フィールドには次を記述：

| 既存フィールド | v2で要求する内容 |
|---|---|
| `axis_positive_case` | ◎の着内再現性を示すレース固有の根拠（事実・比較） |
| `strongest_rival` | 凍結済み印4頭から選んだ最大の軸リスク |
| `relative_axis_case` | ○▲△△を考慮した軸固定判断。**勝ち馬の序列の話だけで終えない** |
| `unverified_assumptions` | コース・距離・隊列・馬場等の未検証前提 |
| `axis_failure_scenario` | **◎が3着以内を外す経路**とその事前根拠 |
| `final_reason` | BまたはCにする比較衡量。元判定から変更するときは相違の理由 |

現行validatorのPASSは**キー・SHA・全件数・馬番等の構造的整合性**を意味する。競馬的な根拠の充足は**別途LLM/人手の品質確認**が必要である。テンプレ文の大量反復、数字をなぞっただけの理由、着外シナリオの不存在は**品質不合格**とする。

品質確認が通らない場合はShadowをFreezeせず修正・再判定し、結果は引き続き未解禁とする。すでに結果を見たBTDAYをv2用に作り直して性能検証に流用しない。

## 6. 前方検証プロトコル

1. **v2本文を結果閲覧より先に独立コミットで固定する**。以後の対象コホート途中で無断変更しない。
2. 既存T2でPrediction→Confidenceを従来どおりFreeze。元A/Zは研究対象外。
3. 正本B/Cの全件に対して上記5問を固有根拠つきで著述。B→Cは2つの追加反証、C→Bは勝ち切り不安と着内安定性の区分を必須。
4. 判定の**品質レビューを行ってから**現行validatorで検査し、結果未閲覧の宣言、元FreezeのSHA・対象件数・印一致を確認。研究原票と検証済みJSONを結果より前に独立コミット／SHA固定。
5. **新しい未使用BTDAYの検証対象と評価指標を結果閲覧前に固定**する。基準・選択対象・未判定や欠測の扱いを途中で成績に応じて変えない。Cの件数不足時は結果閲覧前に追加日数を判断。
6. 正規JRDB SED/HJC結果で◎勝率・◎3着内率・馬連◎流し4点・3連複◎軸6点・5頭BOX10点・◎○2頭軸3連複3点等を比較。全払戻採用、1点100円固定、回収率は総払戻÷総投資。
7. **主要検証項目は元B→Shadow C群の◎3着内率が元B→B群より低くなるか**。副次的に元C→Shadow Bと元C→Cの差を比較する。各群の件数・不確実性・開催差・バージョン差を併記し、1開催／少数Rの偶然に過度な結論を出さない。
8. ◎の3着内率と馬券戦略の利益を混同しない。ROIは配当のばらつきに強く左右されるため、**全件の実払戻と的中件数・投資額・回収額を並記**。高配当を恣意的に除外しない。

### 旧309Rとの比較上の制約

- BTDAY-0152〜0161は**v2を考案するために結果を確認済みの開発標本**。そのレースにv2ラベルを改めて付与しても**独立検証の証拠にならない**。
- 旧v1 Shadowのレース別記録とSHAを残したまま、新標本のv2結果を別系列として集計する。
- BTDAY-0161のConfidence再Freezeは、運用者の説明どおり**結果非参照のフォールバック不具合修正**として扱い、正本として採用。経緯の監査証跡は残し、主要集計から除外しない。
- BTDAY-0160／0161の記述品質への懸念は旧データの監査注記として保持。ただし、過去の当たり外れを根拠にv2の判定閾値・件数を最適化しない。
