## 0. 目的と境界

目的はA/B/Cを正確に再現することではなく、RaceNoteの既存5頭・◎を利用し、実際に購入するレース・買い目・投資点数を結果判明前に選別し、全R一律購入との比較から的中と収支の改善可能性を測ること。

- 全156Rは2周目の開催日再利用。初回独立blind検証ではない。結果知識の間接影響を完全には除外できず、過度な一般化をしない。
- 旧Prediction・Confidence・Shadow Freezeは不変。旧A/B/Cは新たな購入判断への特徴量・根拠として使用禁止。
- 正本ベースライン台帳: `20261116_BTDAY0192_0196_TICKET_RESEARCH_BASELINE_LEDGER.json`。各Rに固定marks・Decision Core SHA・Reader SHAを記載。
- この文書とベースライン台帳は**新しい購入判断をまだ生成／Freezeしていない**。結果・払戻照会を解禁しない。
- 過去の結果・配当・当日最終オッズ・過去開催日の成績／旧Confidenceを新規判定に投入しない。
- 判断に失敗したレースやスキップしたレースも必ず分母に含める。レースごとの欠落を成功率向上のため除外しない。

- Readerの追加現物確認：BTDAY-0193中京11R（14頭）、0194函館11R（15頭）、0195京都11R（16頭）、0196京都11R（11頭）。0194/0195は確認した11Rの全頭で過去ラップ5件、0196では1〜4件と分布に差がある。カバレッジに差があるため、同じ密度の根拠が全レース・全馬に存在すると仮定しない。

- 対象日の当日市場を使わない初期案では、客観的な「期待値プラス／買い得」は確定できない。評価するのは予想に基づく**購入優先順位・的中構造**であり、事後回収率は配当照会後に別評価する。

## 2. 購入前に各レースで判断する情報（LLM著述・根拠紐付け）

1. `race_scenario`: 想定主流展開と成立に必要な条件、対立する展開を明示。Readerのどの記録が根拠か示す。
2. `five_roles`: 凍結印5頭について、各馬の勝利経路、連対経路、3着内経路、当該経路が崩れる条件。印順位の単純置換を禁止。
3. `honmei_axis`: ◎を `WIN`（1着軸）, `TOP2`（連対軸）, `TOP3`（3着以内軸）, `UNSUITABLE`（軸不可）のどれと見るか。順位の強さと3着内安定性を別に説明する。
4. `partner_structure`: ○▲△△のうち、勝ち馬・連対相手・3着内相手としての根拠を識別し、主要相手の敗因も述べる。反対展開で相手が浮上するかを記録。
5. `coverage_risk`: 印5頭外の勝ち馬／馬券内候補に脅かされる可能性と、Readerの実走カバレッジ不足・初条件・展開不確実性を区別。
6. `bet_decision`: `BET` / `PASS`、対象券種・具体的買い目・点数・合計100円単位の支出。PASSも理由必須。絶対的な期待収益は断定しない。
7. `audit`: 参照Reader SHA・Decision Core SHA・禁止情報未使用の申告。

**品質判断**：馬番を置き換えただけのテンプレートは採用しない。文章の重複を消すためだけの言い換えも無効。Readerに差別化根拠が無いときは `insufficient_evidence` と明示し、PASSできる。

- 期待値／購入価値の検証には、対象時点で利用可能な事前オッズ・当日市場ルールが必要となり得る。一方でv056の既存Freezeは当日市場blind。**この初期研究では予想だけの購入選別能力を先に測り、odds-based valueモデルは別版とする。**
