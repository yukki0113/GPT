# RaceNote v0.5.5 Fast Forward Operation

Status: CURRENT OPERATIONAL GUIDE

## Boundary

Automation may perform deterministic transport, validation, grouping, splitting,
hashing, save, Freeze, verify and commit operations.

Automation must **not** perform the race prediction itself.

The mandatory prediction boundary is:

```text
sealed v055 lean Reader
  -> lossless authoring bundle (no omission / no score / no ranking)
  -> LLM reads every race and every runner
  -> LLM authors marks + reasons race-by-race
  -> Prediction Freeze
  -> LLM reviews frozen honmei confidence race-by-race
  -> Confidence Freeze
```

Forbidden inside deterministic automation:

- weighted scoring used to decide marks;
- automatic ranking;
- automatic ordinary-five selection;
- automatic challenger admission;
- automatic honmei/second/shot selection;
- automatic A/B/C assignment;
- generated prediction prose standing in for LLM judgment.

## T1

Use `racenote_v055_forward_turn1.py` after PACI, externally maintained Analysis,
externally maintained RRDB, Course Fit and RaceLap CURRENT have been materialized.

Forward T1 checks freshness for RaceLap only. Analysis and RRDB freshness remain
owned by their dedicated operations.

The wrapper reuses the existing canonical modules and produces:

- DAY PREP;
- market-blind forecast_prep;
- KYI supplemental evidence;
- sealed v0.5.5 Reader;
- `v055/authoring_bundle/<venue>.json`;
- T1 operation handoff.

The authoring bundles contain the complete sealed lean Reader payload for each
race. They do not summarize, score, filter or reorder horses.

## LLM authoring

The LLM reads each venue bundle race-by-race. Each race must still receive an
independent full-field judgment.

The LLM writes exactly two complete drafts:

```text
v055/incoming/llm_decisions.json
v055/incoming/llm_confidence.json
```

`llm_decisions.json` contains the complete v0.5.5 Decision Core for every race.
`llm_confidence.json` contains the separate r4 Confidence review for every race.

These files are prediction artifacts authored by the LLM, not generated by a
deterministic predictor.

For `reader_facing_reason`, the LLM must perform a separate editorial translation
after deciding the race. Internal evidence labels are audit vocabulary, not
newspaper vocabulary. Do not print `IDM`, `RRDB`, `SRB`, `KYI`,
`調教指数`, `状態指数`, Reader/Decision-Core terminology, hashes, or
missing-value tokens. Express the supported meaning in ordinary racing language.

The short note is also independently authored per race. Reusing one
fill-in-the-blanks structure across a card is prohibited; varying horse name,
distance, running style or numeric values does not make a template editorial
prose.

## T2 mechanical finalization

`racenote_v055_turn2_finalize.py` performs only deterministic contract work:

```text
validate complete LLM drafts
  -> split decisions by venue
  -> canonical venue save
  -> Prediction Freeze + verify
  -> save Confidence review
  -> Confidence Freeze + verify
  -> compact completion summary
```

The permanent workflow
`.github/workflows/racenote_v055_llm_turn2_finalize.yml`
runs this finalization when both LLM draft files exist for one daily session.

This removes temporary per-day workflows without moving prediction judgment into
code.

## RaceLap pre-T1 refresh

RaceLap is the only forward evidence whose freshness is owned by T1.

When the accepted RaceLap CURRENT is behind the expected completed-day cutoff,
use the permanent Issue Router route `[RACELAP_FORWARD_REFRESH] <request_id>`.

Issue body is one JSON object with:

- `target_date`
- `expected_period_to`
- `completed_dates` (unique ascending dates; last value equals `expected_period_to`)
- `current_run_id`
- `current_artifact_name`
- `generation_id`

The routed workflow fetches only the explicitly listed completed-day SED archives,
resolves the existing CURRENT, validates the cutoff, and publishes a new Actions
artifact. It does not update Analysis or RRDB and it does not discover dates.

Drive publication of an accepted RaceLap artifact remains a separate native
Google Drive connector operation. Authenticated Drive access is not performed
inside GitHub Actions.
