# AIけんしょーくん 成績画像 設計・運用仕様

> 内部ツール名は画像内に露出せず、公開面では「AIけんしょーくん 成績」として統一する。

- スマホ向け縦長 9:16。
- 近未来ダッシュボード風。
- 可読性を最優先し、濃紺 / 青 / シアン基調。
- 下部に競馬場背景、右下にAIけんしょーくん。
- フッターは `@kensho_10_w`。

## 2. タイトル

`AIけんしょーくん 成績 MM/DD`

タイトル下の副題・メタ情報行は原則置かない。

## 3. カード構成

従来の「◎ 単勝」「◎ 複勝」の2カードは廃止する。

今後は以下の5カード構成を標準とする。

### 3.1 最上段: 自信度A ◎（全幅1カード）

最上段は左右分割せず、横幅いっぱいの1枚カードとする。

表示内容:

- タイトル: `自信度A ◎`
- 着度数: `x-x-x-x`
- 小さな補足: `1着-2着-3着-着外`
- `単勝回収率: xxx%`
- `複勝回収率: xxx%`

目的:

- 全レース◎の単勝・複勝よりも「自信度Aとして強く推した◎がどうだったか」を前面に出す。
- 単勝・複勝の最大的中額が小さくなりやすい問題を解消する。
- 予想画像で導入した自信度と、結果画像を直接つなげる。

### 3.2 2段目

左:
- `馬連 ◎－○▲`

右:
- `馬単 ◎→○▲`

表示内容は従来通り:

- 回収率
- 投資
- 払戻
- 損益
- 代表的中

**集計対象は全レース。自信度Aに限定しない。**

### 3.3 3段目

左:
- `3連複 ◎1頭軸－他印流し`

右:
- `3連単 ◎1着固定－他印流し`

表示内容は従来通り:

- 回収率
- 投資
- 払戻
- 損益
- 代表的中

**集計対象は全レース。自信度Aに限定しない。**

## 4. 自信度A ◎ の集計定義

この節の集計は、**最上段の「自信度A ◎」カードだけ**に適用する。

対象は、予想時点で `confidence == "A"` のレースのみ。

### 4.1 着度数

`x-x-x-x` は以下の順序で固定する。

`1着 - 2着 - 3着 - 着外`

対象レースの◎について、公式確定着順を集計する。

### 4.2 単勝回収率

対象となる自信度Aレースの◎を、各レース100円ずつ単勝購入したものとして計算する。

```
単勝投資額 = 自信度A対象レース数 × 100円
単勝回収率 = 自信度A対象レースの◎単勝払戻合計 / 単勝投資額 × 100
```

### 4.3 複勝回収率

対象となる自信度Aレースの◎を、各レース100円ずつ複勝購入したものとして計算する。

```
複勝投資額 = 自信度A対象レース数 × 100円
複勝回収率 = 自信度A対象レースの◎複勝払戻合計 / 複勝投資額 × 100
```

小数表示は既存成績画像に合わせ、原則小数第1位まで。

## 5. 下段4券種の集計定義

馬連・馬単・3連複・3連単の4カードは、**従来どおり全レースを対象**とする。

- confidence は集計条件に使用しない。
- settlement JSON の各 strategy 集計値をそのまま使用する。
- 投資・払戻・損益・回収率は全レース分。
- 代表的中も全レースから最大払戻を選ぶ。

つまり、自信度Aによる絞り込みは最上段カード専用であり、下段4券種の成績には影響させない。

## 6. データ結合ルール

現行の日次settlement JSONだけでは、各レースの自信度が直接保持されていない場合がある。

その場合は、最上段の「自信度A ◎」を算出するために、以下を `venue + race_no` で結合する。

1. 予想時点の confidence 付き予想JSON
2. 当日の確定settlement / race result

必須取得項目:

- venue
- race_no
- confidence
- ◎ horse_no
- ◎の確定着順
- ◎単勝払戻
- ◎複勝払戻

自信度Aの集計は、予想時点で凍結された confidence を使用し、結果を見て自信度を書き換えない。

下段4券種はこの追加結合を前提とせず、既存 settlement の全レース集計を使う。

## 7. 未確定・異常時

- pending race がある場合、最終成績画像は原則生成しない。
- review_required がある場合、確認完了まで最終画像生成を保留する。
- 除外・取消等で有効な購入対象にならないレースがある場合は、自信度A ◎カードでは対象レース数と投資額から除外し、必要に応じて注記する。
- 自信度A対象が0レースの場合は回収率を `N/A` とする。

## 8. 代表的中

馬連・馬単・3連複・3連単の4カードでは、**全レースを対象に**各券種の `top_payout_tickets` の最大払戻を代表的中として表示する。

例:

`代表的中: 京都 10R 馬単 10,860円`

自信度A ◎カードでは、代表的中は原則表示しない。
上段カードの役割は「A評価◎の精度・回収」を見せることに限定する。

## 9. 色・強調

- 100%以上: 緑 / ミント系のポジティブ強調可。
- 100%未満: 通常の青 / シアン。
- 損益プラス: 緑。
- 損益マイナス: 赤。
- 自信度A ◎カードはゴールドを補助アクセントとして使用可。
- 過度な発光や装飾は避ける。

## 10. AIけんしょーくん

結果の雰囲気に応じてポーズ差分を毎回生成してよい。

例:

- 好成績: バンザイ、サムズアップ、キラキラ、紙吹雪
- 平凡: 腕組み、小首をかしげる
- 不振: ガーン、落ち込み
- 分析的: 考え込む、新聞を見る

キャラクター本体の固定意匠は `../ai-character/README.md` と正本立ち絵に従う。

## 13. X投稿スレッドの責務（2026-10-31追記）

このスレッドは、予想一覧画像に加え、当日の結果・払戻取得、既存の同日精算エンジン実行、成績画像作成まで担当する。

### 13.1 標準フロー

1. GitHub `main` の予想・結果画像仕様、当日freeze済み予想（Social Handoff等）を取得する。
2. `date`、`status`、会場/R、◎○▲△△の完全性を検証し、予想を一切変更しない。
3. 開催後に結果・払戻を取得する。標準は JRDB Result Query（SED/HJC）。同日未入手時の速報は既存同日結果運用仕様に従う。既存の正規ソースがあるなら別ソースで代用しない。
4. 既存 `horse-racing/jrdb/src/racenote_daily_settlement.py` を使用して成績を算出する。買い目、100円単位、戦略別集計を独自に再実装しない。
5. Social Handoff JSONの構造がエンジンのForecast入力契約に一致しない場合は、既存freeze済みForecastまたは `decision_core.marks` を優先して使用する。必要な変換は意味・horse_noを変更せず監査可能にし、無言でフォーマット互換を仮定しない。
6. `settled_races` / `pending` / `review_required`、投資・払戻・回収率、券種ごとの`top_payout_tickets`を検査する。未確定・要確認があれば確定成績画像を公開しない。
7. 最上段だけは予想時点で凍結された `confidence == "A"` の◎を結果と結合して着度数・単複回収率を算出する。
8. 下段の馬連・馬単・3連複・3連単は**全レース**のSettlement値を使用する。
9. 確定値を決定的に文字描画し、画像生成AIに数値・馬名・印を推測させない。キャラと背景は正本デザインに沿わせる。
10. 出力画像の数値をSettlement・自信度A集計と全項目照合する。

### 13.3 処理主体と保存ルール

- ユーザーにSettlement JSONの手動用意を要求することを標準フローにしない。
- 正本の予想・結果ファイルは既存のGit / Drive / Library運用を尊重する。ユーザー添付を恒久的な正本にはしない。
- Settlement JSON/Markdownは再現可能なpost-result生成物。保存する場合も、既存正本との重複・汚染を避ける。
- このスレッドは投稿画像の作成・検算を担当し、予想Freezeの再計算・変更は行わない。
- 独立したSettlementエンジンの再実装はしない。
